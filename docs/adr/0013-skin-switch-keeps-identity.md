# 换皮不动身份

## Status

accepted — 把 ADR-0001 的「本机宠物是 dsh-pet 那只」收窄成「本机宠物的**皮**可以是 dsh-pet 的」。
ADR-0007 的名字归属不变，但切皮这条路径不许走它的写口。

## 背景

这台机器上同时躺着三份宠物素材：`dsh-pet` 的 109 段 WebM、`maodie-pet` 装到
`~/.dsh/dsh-pet/pet/maodie-animation` 的 32 段橘猫、以及 `dsh-local-pet` 自己现有的那份。
其中只有第一份被用上了。

两个事实让"换皮"变成一个真需求，而不是想象出来的：

1. **素材是按目录借的，不是按进程。** `src/pet-assets.js` 只找 `*.webm`；`dsh-pet` 插件关掉之后桌面照常跑，
   因为渲染端读的是包里的文件。所以"换一张皮"不需要对方插件活着——甚至不需要它是一个 DSH 插件。
2. **注册表早就支持多条源，但代码只认第一条。** `src/skin-sources.js` 能装到 16 个源，
   `service.js` 里 `sources[0]` 同时决定了待机池和对外的 `skinId`。所以现在只能"替换"：
   手改 `skin.json` 的顺序、重启 DSH。

反过来，"换皮"很容易顺手改坏另一些东西。`src/service.js` 的改名路径会写 `dsh-pet` 的
`pets[].name`（ADR-0007），本机身份、串门记录、礼物也都在同一片数据目录里
（`identity.json` / `peers.json` / `visits.json` / `backpack.json` / `gifts/`）。
2026-11-04 的决定是：**外观和动作可以换，这些一个都不许动。**

## 决定

**皮是一份资源，不是一只宠物。一只宠物 = 一份身份 + 当前那张皮。**

1. 皮的形状：一个动作目录（每个动作一段 WebM）+ 一个默认尺寸。`skin.json` 里可以有多条源，
   其中恰好一条是当前这张皮。
2. 当前皮由 `settings.json` 的 `activeSource` 指定，缺省取第一条。不新开文件——这是偏好，不是注册表。
3. 换皮只改这一项。`identity.json`、`peers.json`、`visits.json`、`backpack.json`、`gifts/` 一律不写。
4. 换皮不写 `dsh-pet` 的配置。ADR-0007 开给 local-pet 的写口只有「改名」一条路径。
5. 正在播的动作在新皮里不存在时回落待机，不做别名映射。
6. 串门进行中切皮：本地立即重建场景并补发心跳；访客端不主动推送，它们按 `skinId` 缓存，下次取。
7. 皮里的 `size` 只随清单出去（给认不出这张皮的桌面做参考）；本机桌面上所有宠物共用
   一个尺寸（`shared.petScene` 按工作区算、上限 176）。per-skin 尺寸要连带改布局、出生点和
   命中区，另开票——本票不做。

## 考虑过的选项

- **保持 `sources[0]`，让用户调 `skin.json` 的顺序**：能换，但那是"替换"不是"切换"，而且要重启。
  数组顺序本来是注册表语义，不该兼职选择器。
- **每个源一套 helper / 一层窗口**：换皮要重启进程，N 份全屏置顶层又回到 ADR-0005 明确否掉的方案。
- **把当前皮写进 `identity.json`**：身份和外观混在一处，正好违反这条决定——改名和换皮会互相踩。
- **继续让 `dsh-pet` 做唯一源**：等于把"能换别家的皮"这条需求判死，而那只猫的 32 段素材已经在盘上了。
- **per-source 名字（换皮自动换名）**：邻居看到的名字会随皮变来变去，与 ADR-0007 的「一只宠物只有一个名字」直接冲突。

## 后果

- **邻居看到的你跟着变。** 换皮后 `skinId` 变，邻居按新 id 重新拉清单和 WebM。串门记录不受影响——
  `visits.json` 里只有方向、对方名字、开始时间、时长、礼物种类，**没有动作名**。历史天然与皮无关。
- **`skin.json` 要补两个字段**：`idle`（这张皮的待机动作，缺省仍认「待机呼吸休闲」）和
  `once`（一次性动作：不进闲时轮播、播完回待机）。没有它们，别家的「喷火」「打滚」会被当待机无限循环——
  现在的排除表（`点击回应-` / `余额-` / `碎碎念-`…）全是 dsh-pet 的动作名。
- **皮缓存不清理。** `skin-cache` 内容寻址，换回来不用重下。
- **一个已知让步**：换皮那一刻，正在串门的访客还看到旧皮，直到它下次取素材。不做主动推送——
  那要为了一秒的观感新增一条跨端消息。
- 这些是行为约束，靠测试看住：切皮前后 `identity.json` / `visits.json` / `backpack.json` / `peers.json`
  和 dsh-pet 的 `main-config.jsonc` 的内容逐字节不变。
- 换皮只影响本机这一次运行：`skin.json` 的改动仍要重启 DSH 才进注册表（`重载配置` 只重读
  settings，素材源清单在启动时读一次）。

## 后果之外

「皮」进 `CONTEXT.md`。它与「外观包」是同一个形状的两个方向：外观包是客人带来的，皮是我自己正在用的。
这也是为什么它不能是一个只有 dsh-pet 能填的位置。
