# 名字归 dsh-pet，dsh-zoo 只在改名的瞬间写它

## Status

accepted — amends ADR-0001；2026-11-05 修订：接口根本没挂载（404）时直写配置文件（见文末）

## 背景

ADR-0001 定的是"只做桥和影子，不写它的配置"。但一只宠物只有一个名字，而它写在 `dsh-pet` 的 `pets[].name` 里：桌面上那个标签、AI 人设里那句「你的名字是 X」、邻居放行卡上的称呼，源头都是它。dsh-zoo 自己也有一份 `identity.nickname`，只在首次运行时从前者抄一次，之后永不跟随——于是在 dsh-pet 设置页改名之后，主人看到的是新名字，邻居看到的还是旧的。

## 决定

名字的真相是 `dsh-pet` 的 `pets[].name`。dsh-zoo 的 `identity.nickname` 降级成它的**镜像**：每次配置轮询同步，变了就落盘（dsh-pet 缺席时仍有名字可发）并立刻补发广播。

改名由 dsh-zoo 发起时，走 dsh-pet 的官方接口 `PUT /dsh-pet-7340/config`：按下的瞬间读一次、只改 `name` 一个字段、立刻写回；失败就整个不改，由调用方给用户明确失败。除这一条路径外，dsh-zoo 对 dsh-pet 仍然只读。

ADR-0001 那句「不写它的配置」因此收窄为「不绕过它的 API 直接改文件」。

## 考虑过的选项

- **纯只读**：改名继续留在 dsh-pet 设置页。安全，但"在宠物身上改名"这个诉求整个落空——用户要先想起那个跟桌宠无关的设置页。
- **给上游提 PR**：在 dsh-pet 自己的右键菜单里加「改名」，本地永远只读。最干净的长期解，但要等上游发版，且它的桌面菜单在 `src/client/pet.ts` 与 `runtime/electron-helper/sprite.js` 各有一份、必须同步改。
- **本地打补丁**：改 `node_modules/dsh-pet/lib/*.js`。下次 npm 升级（0.3.8 → 0.4.0 已在路上）就没了。

## 后果

- 依赖深了一层：除了 `/state` 和配置文件，现在还依赖 `PUT /config` 这个未承诺接口。它坏了，改名这条路就断，但只读的那一半照常工作。
- `PUT /config` 是**整份配置的读-改-写**。用户正好在 dsh-pet 设置页改别的字段并按下保存时，两边可能互相覆盖。接受这个低概率瑕疵：后果是"名字被改回去，再改一次"，不丢其它字段。
- 空名在 dsh-pet 里是合法状态（回落成宠物 `id`），镜像照抄这个语义，不另立规则。
- 与 dsh-pet 的耦合因此是**两处薄模块**：`src/pet-bridge.js` 读（`/state` + 配置文件），
  `src/pet-name-write.js` 写（改名时一次 `GET` + `PUT /config`）。ADR-0001 的"收敛在一处"
  就此按此收窄，两边各自的失败语义都写在自己文件头上。

## 修订（2026-11-05）：接口根本没挂载时，直写配置文件

现场：一台机器上 `dsh-pet` 的包和 `main-config.jsonc` 都还在，但 profile 的
`dsh.profile.bundles` 里已经没有它，于是它的 `/dsh-pet-7340/config` 路由不存在。
dsh-zoo 用「配置文件存在」判断“装了 dsh-pet”，坚持走写接口 → 每次改名都是
`409 dsh-pet-unreachable`，提示还问「它还开着吗？」——用户既开不了它，也改不了名，
是个死胡同。

**决定**：把「不绕过它的 API 直接改文件」再收窄一条口子——**只有** `GET /config` 拿到
`404`（DSH 对未注册路由的回答，等于“这个实例里没有 dsh-pet”）时，退到读-改-写它的
用户配置文件；超时、连接被拒、5xx 仍然保持原来的整体失败。

理由：

- 404 与“它正在忙”是两种事实。忙的时候它可能正在写同一份配置，绕过 API 会互相覆盖；
  路由不存在时没有第二个写者，竞争窗口为零。
- 名字的真相没有搬家：仍然写进 `pets[].name`。用户以后把 dsh-pet 启用回来，它读到的
  已经是新名字，不会出现“本地叫 A、dsh-pet 叫 B”的分叉。

**代价**：

- 注释会丢。读取要走 JSONC 剥离，写回是 `JSON.stringify`；dsh-pet 自己的 `PUT /config`
  也是这么重写的，所以这不是新增的损失，但确实不可逆。
- 直写保留**整份**配置（顶层字段与宠物字段都不动），比 dsh-pet 的 PUT 更保守——它按白名单
  重建宠物对象，未知字段会被丢掉。

回归：`test/pet-name-write.test.js`（404 才回落、5xx/连不上不碰文件、坏文件原样留着）与
`test/service.test.js`（404 时配置/镜像/快照三处一起变）。
