# 冻住的地块：先解冻，再继续长

## Status

accepted（2026-11-13）。用户要求给冬季来客一个区别于枯萎的"冻坏"状态，并允许花资源解冻。
实现票 75。

前情：[ADR-0021](0021-seasonal-crops-and-withering.md)（枯萎）、
[ADR-0022](0022-seasonal-omen.md)（四季来客）。

## 背景

冬季巨鹿原先复用 `withered`，文案写"冻坏"但行为就是枯萎：只能重种。用户问"冻坏的呢"，
并选择"加上吧，并且现在这个破坏力有点小，可以适当增加"。

需求有两点：

1. 冻住与枯萎要有区别：冻住是**暂停**，作物还在，可以救；枯萎是**死亡**，只能重种。
2. 冬季来客要有存在感，但不能让 idle 玩家离线回来发现地直接没了。

## 决定

**新增 `frozen` 地块阶段，作物保留；花 2 露水 + 5 硬币解冻即可继续长。**

1. **阶段优先级**：`frozen` → `withered` → `empty` → `mature` → `growing`。冻住的地块
   停止生长，`isMature` 为 false，收获产量 0。
2. **限制**：冻住时不能收获、浇水、施肥、重种；访客/看田也不能操作。可以查看。
3. **解冻**：主人点卡片上的「生火解冻」，扣 2 露水 + 5 硬币，清除 `frozen/frozenAt`，
   作物和已积累的生长进度原样保留。资源不足时按钮禁用并说明原因。
4. **换季**：到下一个本地午夜还没解冻，冻住转为 `withered`（冻死），只能重种；不会
   直接删地块或存档。
5. **状态**：`plots[i].frozen === true`、`frozenAt` 为冻结时间；`season.json` 不新增字段。
   日志新增 `freeze`（冻住 N 块）和 `thaw`（解冻一块）。
6. **冬季来客**：巨鹿守卫失败冻 3 块，忽略冻 2 块；这是目前唯一产生冻结的来源。
   春季蛙雨/夏季野火仍用枯萎，不产生冻结。

## 考虑过的选项

- **自动解冻（定时）**：不需要玩家做任何事，冬季来客没有后续压力；否决。
- **解冻需要新道具**：要加背包/商店/配方，超出一次季节事件的范围；否决。
- **永久冻住，必须重种**：和枯萎没区别，用户明确要区别；否决。
- **冻住直接毁地/删档**：idle 惩罚过重；否决。

## 后果

- 冬季来客有独立的失败状态和恢复动作，四个来客的损失类型不再全是"枯萎/作物"。
- 玩家在冬季需要留 2 露水 + 5 硬币，或者接受换季时冻死；这是一个可计算的小决策。
- 冻结不进入 LAN 协议；邻居只看到公开农场视图里的 `frozen` 阶段（若主人开田）。
- 未来若加"温室/火炉"等建筑，可以复用解冻动作，不必改地块模型。
