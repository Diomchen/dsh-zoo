# 桌宠窗口铺满所有屏幕的并集，跨屏拖动不断指针

## Status

accepted — 2026-11-06

## 背景

ADR-0005 定下“一扇全屏透明窗，里面一次画完自己和所有访客”。实现时窗口只覆盖**主屏**工作区，
文档也写着“只保证主屏”。实际用多屏的反馈是：宠物只能在主屏上活动，往第二块屏拖到边缘就停住，
第二块屏上根本没有窗口接收鼠标。

这不是一个坐标算错的 bug：`screen.getPrimaryDisplay().workArea` 从建窗、`ready` 上报到显示器
变化重算，整条链路都只有一块屏。要跨屏拖动，先得让“桌面”这个概念覆盖多块屏。

## 决定

- **一扇窗铺满所有显示器工作区的并集**（`shared.desktopArea()`）。单屏时并集就是那块屏的
  工作区，行为与以前逐像素一致。
- 窗口 bounds、`ready.workArea`、渲染端的物理区域三处必须是**同一个矩形**：`ready.workArea`
  直接上报窗口实际 bounds，宿主按它算场景出生点。
- 宠物**出生在主屏**，尺寸也按主屏算：宿主从 `ready.displays` 里找 `primary`，换算成窗口局部
  矩形后传给 `shared.petScene({ homeArea })`。不这么做的话，两块屏并排时单只宠物正好生在中缝上。
- **走路按“地面带”走**：宿主把每块屏的工作区换算成窗口局部矩形，随场景下发 `floors`；
  渲染端用 `shared.walkBands()` 把底边相同且水平相邻的屏合成一条带，`shared.bandAt()` 找
  宠物所在带。走路只在带内（x 夹在带边界、y 贴带底边）：同高并排的屏可以来回走；高度不同
  的屏各自一条带，走到接缝就停住，不会掉进矮屏下方那块没有显示器的黑区。拖拽仍用整张并集，
  松手时 `shared.confineBodyToBand()` 把 x、y 都夹回落点所在的带。
  单屏时只有一条带，结果与旧行为逐像素一致。
- 插入/拔出/改分辨率时重算并集、重设 bounds、重发 `ready`，宿主重算 `homeArea` 与 `floors`。

## 考虑过的选项

- **每块屏一扇窗**：桌面画得更“原生”，混合 DPI 也不糊。但跨屏拖动做不到——指针捕获不能跨窗口，
  光标离开 A 窗就没有 `pointermove`/`pointerup` 了；要么在接缝处把手势交接给 B 窗（Electron
  没有这个原语），要么拖到边缘就断。放弃。
- **拖动时让窗口跟着光标移动**：仍是一扇窗，但整个场景会随拖动平移，其他宠物的位置、弹层锚点、
  命中矩形都要跟着换算，而且宿主下发的场景坐标不再稳定。为一个手势把整层坐标系变成可移动的，
  代价远大于收益。放弃。
- **只把 `ready.workArea` 改成并集，窗口仍只覆盖主屏**：宿主会把宠物放到窗口外，第二块屏上依然
  看不见也点不到。等于只改了协议、没改现实。放弃。
- **地面直接取并集的下边界**：代码最少，但笔记本 + 外接屏这种高度不一致的摆法里，矮屏上的宠物
  一出生就掉到屏幕外。把每块屏的局部矩形随场景下发（`floors`）多几十行，换“矮屏上看得见”，值得。
- **只按“脚下那块屏的底边”改 y、不改 x**：第一版就是这样，现场立刻发现：从矮屏往高屏拖、
  在黑区里松手时，最近的屏可能是旁边的高屏，y 被夹回高屏底边、x 还停在黑区里，宠物就消失在
  矮屏下方的黑边。改成“地面带”后走路连 x 一起夹，松手也把 x 夹回带内。
- **合并 `display.bounds` 而不是 `workArea`**：能盖住菜单栏/任务栏，但宠物会走到菜单栏上，
  点击判定也会和系统 UI 抢地盘。选 `workArea`。

## 后果

- 跨屏拖动、点击、访客出现都按整张虚拟桌面工作；`hit.rect` 仍是屏幕坐标。
- **走路有边界**：同高相邻的屏合成一条地面带，可以来回走；高度不同的屏各自一条带，走到接缝
  就停住（不会掉进矮屏下方的黑区）。拖拽仍然可以跨屏，松手时 x、y 都夹回落点所在的带。
- 非矩形摆法下并集包含空洞：宠物可以被拖过空洞；松手按水平范围回到脚下那块屏，
  x、y 都夹回可见范围。读取位置时不要假设 “宠物一定在某块屏里”。
- 混合缩放比的屏并排时，Chromium 只能给一扇窗一个 device scale factor，非主屏一侧可能略糊；
  坐标判定仍按 DIP。`enableLargerThanScreen: true` 保留，窗口允许大于单块屏。
- 一扇窗覆盖的面积变大：点击穿透的 fail-closed 机制（`forceIgnore()`、租约过期、宿主失联）
  一个都不能少，否则挡住的是整张桌面而不只是一块屏。
- 回归由 `test/desktop-multi-display.test.js`（用假 Electron 跑真 `desktop/main.js`：
  左/右并排、负坐标、拔屏收回）、`test/desktop.test.js`（`desktopArea` / `homeArea` 纯函数）
  和 `test/service.test.js`（宿主把宠物生在主屏）看住。
