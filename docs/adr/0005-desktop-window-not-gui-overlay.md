# 桌宠换成独立的全屏透明窗，取代 GUI 浮层

## Status

accepted — supersedes ADR-0004

> 后记（ticket 13）：改名需要有地方收键盘，所以多了一扇**独立**的小窗（`desktop/rename.html`）。
> 主窗那条约定不变：它仍然只有一个、全屏、`focusable: false`；可聚焦的只有那扇临时小窗。

## 背景

ADR-0004 把 v1 定成"只做 GUI 浮层，桌面层推迟"。实际用下来，浮层把宠物关在了 DSH 窗口的右下角：不挡界面、点得穿、也看不见它走动。用户的第一句反馈就是"为什么限制在这个框内"。

## 决定

宠物活在桌面上，不在应用里。宿主另起一个 Electron helper 子进程（复用 `~/.dsh/electron/Electron.app`），开**一个**全屏透明、无边框、置顶、点穿的窗口，里面一次画完自己和所有访客。

## 考虑过的选项

- **继续用 `shell.overlay`**：零新进程，但宠物永远出不了 DSH 的窗口，正是用户不满的那一点。
- **学 dsh-pet 一宠一窗**：能让每只宠物各自独立，代价是 N 份进程 + N 套逐帧 bounds 同步；它自己的源码为多屏 DPI 坐标跳变写了一百多行注释。我们一个窗口画全部，物理和渲染共用一份 React 树。

## 后果

- 宿主是 `ELECTRON_RUN_AS_NODE=1` 的纯 Node，拿不到 `BrowserWindow`——所以必须有 helper 子进程。它崩了就是没有宠物，不能影响宿主。
- helper 与宿主之间走 stdio 的 JSON 行，不开新端口：DSH Desktop 会拦插件子进程的裸 HTTP（dsh-pet 踩过）。
- 窗口默认点穿，只有光标进入宠物命中矩形时才临时接管鼠标。这条必须做对，否则一个置顶全屏窗会把整台机器卡死——所以要有"杀掉 helper 就恢复"的兜底。
- v1 的 `shell.overlay` 那一整块（灯、访客、卡片、拖拽出门）随之删除，代码留在 `v0.1.0`。
