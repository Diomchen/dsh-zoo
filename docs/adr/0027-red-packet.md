# ADR-0027：带派红包

**Status:** accepted
**Date:** 2026-11-16

## Context

带派（ticket 11 / 24）原本只能捎两样东西：一条字条，或一个文件。农场（ticket 40 起）里
攒下的硬币、作物、种子没有“社交出口”——想分一点给邻居，只能让对方来偷菜，或者自己去
交易所卖掉，中间没有任何“我送你”的动作。

红包要解决的就是这件事，但直接照搬聊天软件会踩三个坑：

1. **先扣还是后扣**：如果拆开时才扣发送方，发送方可能已经把硬币花掉，红包就成了空头；
   如果拆开时才加给接收方，又要处理“红包过期时东西在哪”。
2. **会不会凭空消失**：24 小时没人拆，红包里的东西既不能留在网络里，也不能悄悄蒸发；
   邻居离线时更不能靠“重发”解决。
3. **会不会重复给**：局域网里消息可能重放，访客重连也可能重发同一个礼物；红包里的东西
   必须恰好给一次。

带派现有的模型是“宿主算数据、helper 只画”，礼物本体落在 `gifts/<目录>/meta.json`，
发送前先进背包（最多两件）。红包沿用这套模型，只是把 payload 从 text/file 扩成 packet。

## Decision

- **红包是礼物的一种 kind**：`gift = {id, kind:'packet', packet:{coins,crops,seeds}, note?}`，
  与 text/file 共用访客握手、回执、背包和礼物卡，不新增一套投递通道。
- **寄出即扣**：`bring` 时先从自己农场扣硬币/作物/种子（`spendCoins`/`takeCropOf`/
  `takeSeedOf`，失败整体回滚），再进背包。背包里撤回则原样退回农场。
- **拆开才到账**：接收方点「拆开」（`gift-claim`）才把内容加进他的农场；不加就一直是
  `received`。拆开是一次性的：先写 `claimedAt` 再发货，发货失败回滚 `claimedAt`。
- **24 小时退回**：未拆的红包在 `receivedAt + 24h` 后由宿主定时器标记 `returnedAt`，
  并尽力发 `packet-return` 给发送方；发送方收到后把内容加回农场并回 `packet-returned`。
  对方离线就留在重试表里，下次上线补发；红包永远不会“消失”，最坏是停在「待退回」。
- **额度**：硬币 ≤200、每种作物/种子 ≤20、作物和种子各 ≤5 种、祝福语 ≤60 字、
  每天最多寄 3 只（按本地日重置）。额度在宿主和 helper 各校验一次，helper 只夹紧不放宽。
- **只进农场，不进背包**：拆开的内容直接记到农场（硬币、作物、种子），不占背包格。
- **账本落盘**：`meta.json` 记 `kind/packet/note/receivedAt/opened/claimedAt/returnedAt`；
  重放同一个 `gift-claim` 返回 `packet-claimed`，重放 `packet-return` 不重复加东西。
- **协议**：新增两个包类型 `packet-return`（带 `giftId`/`contents`/`note`）和
  `packet-returned`（只带 `giftId`）；两者都不进 `VISIT_TYPES`，不参与访客身份重建。

## Consequences

- 红包在“寄出 → 背包 → 串门 → 拆开”这条链上每一段都有明确归属，任何一步失败都能回滚。
- 邻居离线时红包不会丢：`packet-return` 有重试表（上限 200 条），过期红包保持
  「待退回」状态直到对方回来。
- 每天 3 只 + 单只 ≤200 硬币，配合交易所价格，单日最大转移量有限，不至于把经济打穿。
- 拆开不加背包，所以背包永远只有 2 格；收红包不会挤掉已有的字条/文件。
- 协议多了两个类型，旧版本收到会当未知类型忽略（握手继续），不会崩；但旧版本发不出红包。

## Alternatives considered

- **拆开时才扣发送方**：发送方可以先把硬币花掉，红包变空头；丢弃。
- **自动到账（不用点）**：访客一到就把东西塞进农场，用户没有“收不收”的动作，
  也容易出现“我不在电脑前，东西已经进来了”；用户明确选了点「拆开」。
- **过期直接销毁**：违反“邻居离线也不能吞东西”；丢弃。
- **红包内容进背包**：会挤掉背包里已有的字条/文件，且背包上限只有 2 格；丢弃。
- **单独一套红包协议/通道**：要重做握手、回执、限流、重放保护，收益只是少一个 `kind`；
  丢弃。

## 补记（1.7.2）：发件前先问对方认不认识

上线后发现的真实事故：红包「寄出去了」，对方什么都没收到。

原因是 1.6.5 之前的 `normalizeGift` 只认 `text`/`file`，遇到 `kind:'packet'` 会**整件丢掉**，
而 `visit-ack` 依然按串门成功回执——发件方看到的是「送出去了」，背包里那件也跟着出门，
红包和里面的硬币就这样静默蒸发。

修法不只是在本地报错，而是**发送前确认能力**：

- `CAPS` 增加 `packet`（心跳/beacon 一起带，仍在 4 个上限内）。
- `startOutboundVisit` 取背包最旧一件时，若它是红包且目标邻居没有声明 `packet`，就不带走它：
  `packetHeld: true` +「对方版本还不支持红包，这次先帮你留在背包里。」，串门照常。
- 老邻居（≤1.7.1）不声明这个能力，所以升级前后都能安全：红包留在背包，不会消失。

代价是 1.6.5–1.7.1 之间「其实能收红包」的邻居也会被扣下——他们升级后即可恢复，
这比静默丢失更好。
