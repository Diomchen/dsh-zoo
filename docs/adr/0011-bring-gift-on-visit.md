# 带派：礼物随串门走，拉取不推送，回执才算送到

## Status

accepted

## 背景

串门到现在只交换三样轻东西：我是谁、我在干嘛、我说一句（ADR-0008）。用户要的是：
**出门前能给宠物带一件东西**——一段文字、一张图片、一个文件——到了邻居家留下。

三个既有约束决定了这件事的形状：

1. **UDP 报文上限 4 KiB**（`src/protocol.js`），文件本体永远不可能走心跳或串门报文。
2. **已经有一个只读的局域网 HTTP 服务**（素材源，ADR-0008 的「拉取，不推送」），
   端口随 beacon 广播，路径白名单 + sha256 校验。但它在**没有素材源时不会启动**。
3. **桌面主窗 `focusable:false`、没有拖拽**（ADR-0005），能打字的只有改名那扇独立小窗。

还有一条产品事实：入站访客**没有 TTL**，来就常驻，直到「送客」或对方失联。所以礼物不能
依赖"访客很快就走"这个假设，也不能做成一次性的弹窗。

## 决定

**一次串门可以带一件礼物。它随串门抵达，留下就是对方的；送没送到，以对方的回执为准。**

具体：

- **一次一件**。要么一条**字条**（内联在 `visit-request` 里，≤500 字），要么**一个文件**
  （≤16 MB；图片额外在桌面上给缩略图）。不做文件夹、多选、URL 卡片。
- **字条随报文，文件靠拉取**。文件由接收方在访客抵达时主动来取：
  对方在**既有的素材源端口**上开一条礼物路由，接收方校验大小与 sha256 后才落盘。
  视频、图片、压缩包本体永远不进 UDP。
- **送达以回执为准**（新增 `gift-received`）。接收方真的把文件写进 `gifts/` 之后才回一条；
  发起方收到才把礼物从背包里删掉。串门结束还没收到 → 退回背包，并在本机说一句人话。
  没有回执的"发出去就算送出"会在防火墙挡住素材端口时**静默吃掉**用户的礼物，
  而那正好是最常见的失败（UDP 通、TCP 被挡）。
- **礼物落在隔离目录**：`<dataDir>/gifts/<giftId>/`，里面是原文件（或 `note.txt`）+ `meta.json`
  （谁捎的、原名、大小、sha256、到达时间）。**永不自动打开**；卡片给
  「打开 / 在文件夹里显示 / 扔掉」，字条额外给「复制」。
- **礼物卡跟着这次串门**：访客回家卡片就收起，礼物留在磁盘。送客时若一次都没打开过，
  冒一句提醒，别让东西被悄悄遗忘。
- **背包**（`<dataDir>/backpack.json`）：最多两件，先放的先带走；可手动撤掉；没送到的退回来。
  手动出门可以现挑，自发出门从背包里带最旧的一件——自发出门是这个插件的主线，
  不能让它永远空手。
- **入口**：右键自己的宠物 →「带派」开一扇 focusable 小窗（复用改名窗那套），
  同时开 `POST /local-pet/action {"action":"bring"}`，让脚本和别的插件也能用。
- **礼物只随串门**。被拒绝、超时、对方关掉了串门 = 没送到；不做「只把东西带过去、人不进门」，
  也不做「递给访客让它带回家」——那是另一套路径。
- **不设单独的「不收礼物」开关**。礼物是串门的一部分，关掉串门就等于不收；
  安全边界放在：只收放行过的邻居、单件/总量/频率限额、隔离目录、永不自动打开。

## 考虑过的选项

- **把文件切块塞进 UDP**：4 KiB 上限、丢包、无重传，等于自己写一个不可靠的传输层。否。
- **另开一个礼物专用端口**：多一次防火墙询问、多一套要守住的服务。复用既有只读服务更省。
- **新版本升级协议版本号**：不必。礼物是可选的单字段，旧端解析时丢弃未知字段，行为不变；
  新端缺字段时退回老行为——与 ADR-0008 的扩展方式一致。
- **接收端先问「收下吗」**：把串门变成审批流，还要一条「拒收」回传路径。放行已经是信任门槛，
  再问一次只增加摩擦。用户想丢掉时点「扔掉」就行。
- **礼物写进 `~/Downloads`**：和用户自己的文件混在一起，删除与清理都说不清；隔离目录才有
  「扔掉 = 删掉那一个目录」这种干净的操作。
- **加 `accept-gifts` 开关**：会出现「能来串门但东西被悄悄退掉」的第三种状态，
  解释成本大于安全收益。

## 后果

- 多一个报文类型（`gift-received`）和一个「捎出中」状态。一次出门只带一件，状态很小。
- **没装素材源的用户也会监听一个局域网只读端口**——这是这个功能真正新增的攻击面。
  必须守住：只按 id 白名单取、只在 armed 期间可读（串门发出后 5 分钟、未结束）、不列目录、
  不信任何报文里的路径。
- 磁盘会涨：`gifts/` 上限 500 MB / 200 件，超了按最旧删；同一邻居每小时 ≤10 件、每天 ≤50 件。
- 旧版本对方会忽略 `gift` 字段，于是发起方表现为「没取到」，不是崩溃。
  「没取到」的文案必须诚实写到「可能没开端口、或对方版本较旧」，不能假装知道原因。
- 字条和文件两种形态要在卡片、记录、状态出口各分一次支。记录只记 `gift.kind` 与文件名，
  **不记字条正文**——历史文件会被翻看，不该替用户保存私房话。
