# ADR-0026：自适应局域网行情指数

**Status:** accepted
**Date:** 2026-11-16

## Context

交易所原本把本机价与邻居指数按固定 `85% / 15%` 混合。只有一家邻居时，
指数几乎不影响成交；邻居多了也还是 15%，交易所像一个个孤岛。
直接把权重提到 75% 又会让单家邻居主导价格，且一次报价异常就能把整行价格拽走。

目标是“邻居越多越像同一个市场”，同时保留本机供需和不同作物的性格：
番茄、草莓这类快周转作物跟邻居慢一点，西瓜、葡萄这类高价值作物跟得快一点。

## Decision

- 权重按**新鲜邻居数**分档：0 家 0%，1 家 45%，2 家 65%，3 家及以上 75%。
- 再乘**作物 beta**：番茄/草莓/豌豆 0.8，白萝卜 0.9，胡萝卜/稻米 1.0，
  玉米 1.1，南瓜 1.3，西瓜/葡萄 1.4；未知/自定义作物按 1.0。
- 有效权重封顶 **85%**，避免高 beta 把本机价完全抹掉。
- 指数 = 新鲜 peer 报价的中位数；再叠加 peer 最近一轮涨跌的中位数作为**动量**，
  单轮夹在 ±12%，最终价格仍夹在 `[base×0.5, base×2]`。
- 没有新鲜邻居时指数退化为本机价、`samples:0`，不伪造“有邻居”。
- 只影响卖价 `bid`；买种子仍按固定种子价。
- `/state.market.index` 保持 `{price,at,samples}`；只有窗口视图额外带
  `weight/momentum/stale`，避免破坏旧客户端。

## Consequences

- 两家邻居时番茄有效权重约 52%，西瓜约 85% 封顶；一家邻居时分别约 36% / 63%。
- 邻居整体涨价时，指数会先冲高再随报价回落，形成可感知的趋势；
  单家异常报价仍被中位数和 ±12% 动量夹住。
- 旧 `market.json` 没有 `momentum` 时按 0 读入；之后随新 digest 自然补齐。
- 若邻居长期离线，窗口保留最后一次指数并标 `stale`，但不参与成交价。

## Alternatives considered

- 固定 75%：单邻居时风险过高，丢弃。
- 只按邻居数、不乘 beta：高价值作物和快周转作物对邻居的敏感度一样，缺少“股市感”。
- 引入全局服务器/互联网行情：与局域网、无中心的架构冲突，超出范围。
