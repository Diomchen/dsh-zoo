# v1 只做 GUI 浮层，桌面层推迟

## Status

superseded by [ADR-0005](./0005-desktop-window-not-gui-overlay.md)
（v1 的决定只在 v1 成立；v2 已把宠物搬到全屏透明桌面上）

## 背景

用户平时看的是 `dsh-pet` 的**桌面层**（透明置顶窗），不是 GUI。而"加一块自己的浮层"在 GUI 里有一个官方座位（`shell.overlay`，点穿、不挡界面、不进滚动容器），在桌面层则要复刻 `dsh-pet` 的一整套窗口管理：每只宠物一个透明无边框置顶窗、一个 helper 子进程、以及一条绕开 DSH Desktop 访问闸门的自定义 scheme + stdio 桥。

## 决定

v1 的客厅只活在 DSH GUI 的浮层里。桌面层不做。

## 考虑过的选项

- **只做桌面层**：串门看起来最自然（两只浮窗在桌面上相遇），但 v1 的预算会全部花在窗口管理和跨机器窗口定位上，协议和信任模型反而没时间做对。
- **两层都做**：等于同时开两个项目。

## 后果

- **v1 有一个已知的体验缺口**：用户如果不打开 GUI，就看不见串门。这必须在验收时被明确指出，不能被当成"能用"。
- 客厅里因此也画一只**本地影子**（跟随 `dsh-pet` 当前动作的那只自己），否则"我的宠物出门了"在客厅里没有视觉主语。
- v2 若做桌面层，协议不用改：意图同步与渲染层无关。
