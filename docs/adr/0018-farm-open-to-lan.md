# 农场是公开的：放行只管「来玩」，不管「来拿」

## Status

accepted（2026-11-11）

规格：[SPEC v7](../../.scratch/dsh-zoo/SPEC-v7.md)；票 51–54 在
[`.scratch/dsh-zoo/issues/`](../../.scratch/dsh-zoo/issues/)。
取代 [ADR-0016](0016-farm-economy-federated.md) 决定 4 的前半句（「放行邻居 + 活跃串门」）。

## 背景

v1.1 起，偷菜和看田都得先串门：`GET /dsh-zoo-farm/<visitId>` 只认活跃访客
（`src/service.js:2425`），`farm-action` 也认同一个 visitId（`src/service.js:3928`）。
于是想偷一次要走四步：放行 → 出门 → 到了 → 在小窗里找地。

用户的原话是：「我希望直接能查看邻居农场，所有装了插件的都需要强制开放」「这样就可以
直接偷菜」，被追问"要不要留开关"时回答「都关了有什么意思」。这不是要一个更方便的入口，
是要**换一种关系**：邻居的农场是可以看的、可以拿的，不需要先被允许。

值得先记下来的是：这套协议里**没有任何身份验证**。deviceId 是自称的，报文是明文 UDP，
`mayTalkTo` 只是一张 UUID 白名单（`src/room.js:1117`）。所以「放行」从来不是一道安全边界，
它是一道**社交边界**。这条 ADR 移动的正是这道社交边界。

## 决定

**放行（admit）只控制"宠物能不能出现在我的桌面上来玩"；看田和偷菜不受它约束。**

1. **看不需要放行**：任何被发现、且支持 v1.3 的邻居，都能在家打开它的农场（只读）。
2. **偷也不需要放行**：派宠物去偷，对面不能拒绝，也不需要先放行过它。
3. **偷仍是一次行程**：宠物真的出门，**并且出现在对方桌面上**（`kind: 'raid'`，带「偷菜」
   角标）。它自动按额度偷完就回家。出门照旧让自家农场没人看（守卫 0）。
4. **防线是概率、额度、记账，不是身份**：守卫（主人在家 0.3 / 有雇工 0.8 / 不在家 0）、
   每块地每轮 1 次、一趟额度、日上限、主人日志和 toast。**不做"谢绝偷菜"开关，也不做
   "谢绝被看"开关**——用户明确不要，这两样会让"强制开放"变成"默认开放"。
5. **公开视图脱敏**：只给地块（作物/阶段/剩余时间）、守卫、以及**请求者自己**的次数和
   `stolenByMe`/`helpedByMe`。不给仓库、硬币、种子、别人的 deviceId，不给任何路径。

## 考虑过的选项

- **只对已放行邻居开放**：最保守，但会把用户的原话降级成"半开放"——没放行我的人偷不了我，
  我也偷不了没放行我的人，"强制开放"就没了。
- **默认开放但留一个开关**：用户明确否掉（"都关了有什么意思"）。而且开关一存在，
  它就会变成"谁关谁占便宜"的博弈。
- **纯远程、宠物不出门**：最省事，但守卫和驮包同时失去意义——"我出门了所以家里没人看"
  这个张力是农场唯一的时间成本。
- **删掉放行**：会把串门、礼物、记录一起拖下水。留着它，它还有明确含义：**来玩要你点头**。
- **只放开门、不开桌面（偷客不出现）**：比本决定更温和，但用户选了"出现"——被偷的人
  应该看见那只宠物真的干了这件事，而不是只看到一条日志。

## 后果

- **农场对所有装机者可见、可拿**：这是这台机器上一个不可撤销的姿态（没有 UI 能关）。
  局域网之外的不可达（`isPrivateAddress` 只允许私网/回环）。
- **`acceptVisits` 的含义收窄**：它仍然只管入站串门（来玩），不拦偷客。
- **新报文面**：`visit-request` 多一个 `purpose` + `plots`，`visit-ack` 多一个 `raid` 结果；
  beacon/heartbeat 多一个 `caps`。老版本邻居会把这些当成普通串门（然后按"没放行"拒绝），
  界面上要显示成"对方版本太老"，不能显示成"被拒绝"。
- **术语要改**：`perVisit` 变成"每趟"（`perTrip`），"访客"要能区分 `kind: 'raid'`。
  CONTEXT 与 SPEC v7 同步。
- **旧邻居只能串门**：v1.2 及更早没有远程视图，也没有免放行的偷；它们之间的偷菜仍是
  v1.1 的串门流程。
