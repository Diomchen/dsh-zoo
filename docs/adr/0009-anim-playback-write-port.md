# 点播写口：只写 dsh-pet 的 `/anim`，其余仍然只读

## Status

accepted — 收窄 [ADR-0001](0001-bridge-dsh-pet-not-fork.md) 的「只读」，与 [ADR-0007](0007-name-belongs-to-dsh-pet.md) 并列的第二个写口

## 背景

[ADR-0001](0001-bridge-dsh-pet-not-fork.md) 把 `dsh-pet` 定为**只读**的桥：只读 `/state`、只借
`/thumb` 的素材路由，不写它的配置，也不调用 `/anim`。

桌面右键菜单把「动作」这一支搬过来之后，这条只读立场撑不住了。原因不是"想写"，是**不写就没有
诚实的实现**：

- 影子只镜像 `/state` 的 `pets.<id>.anim` 叶子，而 `/state` 每秒拉一次。渲染端在本地播一次，
  下一个 tick 就被回落成待机——用户看到的是点完闪一下。
- 邻居通过协议看到的是**宿主上报的动作**。本地播而不写本体，等于让邻居看见一只正在"写代码"、
  实际上在打盹的宠物。

所以点播必须落在本体上：**本体播 → `/state` 回灌 → 影子跟着播 → 邻居也看到同一个动作**。
一条真相，三个地方一致。

## 决定

- 新增**唯一**的写口：`POST /dsh-pet-7340/anim?pet=<id>&surface=any`，body
  `{ "name": "<动画名>" }`。这就是 dsh-pet 自己右键菜单点「动作」走的那条路，效果与它完全一致。
- `surface` 是它 0.3.8 起的**必填**参数（缺了直接 `bad-request`）。dsh-zoo 不是它的任何
  一端，只镜像 `/state`，所以明说 `any`：只要那只宠物显示在任意一端就受理；`display: none`
  由它自己拒掉，我们不去猜。
- 名字先用**同一份** animations 配置筛一遍（菜单的树就是从它建的），理由是它自己也会校验：
  名字不在集合里 → `200 { ok:false }` → 表现为"点了没反应"。我们要在发出去之前就拦住。
- 仍然不写它的配置文件。改名的 `PUT /config` 是 ADR-0007 早就开的口子，本 ADR 不扩大它。
- **失败与降级**：不可达 / `ok:false` / 超时 → 渲染端在本机播一次，并在这一段播完之前不跟
  `/state` 覆盖。菜单可以降级，但不能"点了没反应"。

## 考虑过的选项

- **只在本机播一次**：改动最小，但会闪（1 秒后被 `/state` 覆盖），而且邻居看到假动作。
- **自己实现动画播放**：那就是 fork dsh-pet，ADR-0001 已经否过，长期债最重。
- **直接写它的配置文件绕过 API**：ADR-0007 已经把这条路封了（只走 API）。
- **走它的 `/broadcast` 推气泡说"我在写代码"**：那是它的话，不是它的动作；影子仍然不会动。

## 后果

- 多依赖一个**未承诺接口的写面**。它改端点或改校验，点播就会失败。失败必须有人话提示 +
  本机降级，绝不能静默。
- 菜单里的动作集合必须与它的 animations 配置**同源**。改配置格式就得跟着改，读不到就降级成
  本机素材源的平铺清单（动作名 = 文件名），那条路不需要 dsh-pet。
- 影子与本体的一致性继续依赖 1 秒的 `/state` 轮询——这一条本来就存在，本决定不新增延迟。
- 点播是**用户手动**动作。自动轮播、事件动画仍然是它自己的事，dsh-zoo 不掺和。
