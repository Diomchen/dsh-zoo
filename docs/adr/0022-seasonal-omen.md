# 季候来客：卡片式的一次选择，不做实时 boss

## Status

accepted（2026-11-13）。用户选择 v1 带一个秋·熊獾、中等惩罚。
实现票 67 / 68 / 70。

前情：[ADR-0020](0020-season-clock.md)（季节时钟）、
[ADR-0021](0021-seasonal-crops-and-withering.md)（四季作物与枯萎）。

## 背景

饥荒的季节事件核心是"压力"：春天蛙雨、夏天野火、秋天熊獾、冬天巨鹿。它让季节不只是
换作物，而是"今年要怎么活"。但 dsh-zoo 是 idle + LAN：

- 玩家可能几小时不看窗口；实时 boss/倒计时会变成离线惩罚。
- 没有战斗、HP、寻路、动画系统；为一次季节事件加一套实时战斗不划算。
- 已有守卫、雇工、仓库、偷菜/帮忙、日志；来客应该复用这些，而不是另起一套。

用户要"饥荒里面的季节事件也可以考虑"，同时接受"v1 只做一个、中等惩罚"。

## 决定

**来客是一张卡：出现时做一个选择，立即结算；不做实时 boss。**

1. **v1 只做秋·熊獾**：秋天那一天出现，每 4 天一轮一次；不是每天。
2. **两个选择**：
   - 守夜（`guard`）：成功率 = 当前守卫（主人 0.3 + 雇工 0.5，封顶 0.8）。
     成功 +40 硬币 +3 露水；失败仓库失去最多 3 个作物。
   - 投喂（`feed`）：仓库至少 3 个作物；消耗 3 个，+1 稻米种子 +2 露水。
3. **不处理**：换季结算时仓库失去 1 个作物；记一条日志。
4. **中等惩罚**：只动仓库作物，不毁地块、不删档、不扣硬币；失败最多 3 个，忽略 1 个。
5. **状态** `season.json` 的 `omen: { start, id, resolved, choice, result }`；
   `resolved` 后不重复弹；换季未解决由 service 结算一次。
6. **只给主人**：访客/看田模式不显示来客卡；来客不进入 LAN 协议，不影响邻居。
7. **掷骰注入**：用 `farmRandom`；测试可固定成功/失败。

## 考虑过的选项

- **实时 boss（HP/倒计时/桌面巨兽）**：最有饥荒味，但需要新实体、寻路、动画、LAN 同步、
  离线处理；v1 范围爆炸；否决。
- **每天来一次**：1 天 1 季会让来客变成每日打卡，和每日节日抢注意力；否决。
- **四个来客一起上**：野火/巨鹿要动地块，需要"烧毁/冻结"新状态；先做一个只动仓库的，
  验证卡片模式；否决。
- **硬惩罚（毁一块地/全枯）**：idle 玩家离线回来发现地没了，挫败感太强；否决。
- **纯奖励、无代价**：来客变成又一个节日，失去"季候压力"；否决。

## 后果

- 季节有了"正向节日 + 偶发压力"两层；玩家在秋天会多看一眼仓库。
- 来客频率低（4 天一次），不会压过每日节日；错过只损失 1 个作物，可接受。
- 守卫/雇工/仓库被重新使用，没有新增战斗系统；未来四个来客可以复用同一张卡的结构。
- 来客是本地事件，LAN 邻居看不到；如果以后要做"邻居协防"，需要新的协议与权限，
  不在本 ADR 范围内。
- 读系统时间可以"跳过"秋天，但也会跳过节日/作物；这是本地时钟游戏，不做防作弊。
