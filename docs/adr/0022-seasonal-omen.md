# 季候来客：卡片式的一次选择，不做实时 boss

## Status

accepted（2026-11-13）。用户选择 v1 带一个秋·熊獾、中等惩罚；v1.6 扩展到四季来客、
随机 3 小时窗口，并提高破坏力。实现票 67 / 68 / 70 / 74 / 75。

前情：[ADR-0020](0020-season-clock.md)（季节时钟）、
[ADR-0021](0021-seasonal-crops-and-withering.md)（四季作物与枯萎）、
[ADR-0023](0023-frozen-plots.md)（冻住与解冻）。

## 背景

饥荒的季节事件核心是"压力"：春天蛙雨、夏天野火、秋天熊獾、冬天巨鹿。它让季节不只是
换作物，而是"今年要怎么活"。但 dsh-zoo 是 idle + LAN：

- 玩家可能几小时不看窗口；实时 boss/倒计时会变成离线惩罚。
- 没有战斗、HP、寻路、动画系统；为一次季节事件加一套实时战斗不划算。
- 已有守卫、雇工、仓库、偷菜/帮忙、日志；来客应该复用这些，而不是另起一套。

用户要"饥荒里面的季节事件也可以考虑"，先接受"v1 只做一个、中等惩罚"；随后要求
"其他的季节事件也开始开发，出现时间改成随机，持续 3 小时"，并要求"破坏力适当增加"。

## 决定

**来客是一张卡：在随机 3 小时窗口内出现，做一个选择，立即结算；不做实时 boss。**

1. **四季各一位**：春·蛙雨、夏·野火、秋·熊獾、冬·巨鹿。
2. **出现窗口**：蛙雨/野火在当天随机一个整分钟出现，熊獾/巨鹿固定在本地 15:00 出现；
   都持续 3 小时。随机窗口用 `${season.start}:${id}` 的哈希决定，重启/重开窗口不会换时间。
   窗口外不显示卡片，也不能结算。
3. **两个选择**，内部 id 固定为 `guard` / `feed`，标签随来客变化：
   - 守卫：基础成功率 = 当前守卫（主人 0.3 + 雇工 0.5，封顶 0.8）。来客卡上可临时雇 0～2 名守卫，
     每名 20 硬币、+0.5，最终封顶 1.0；费用结算时先扣，失败不退。成功拿硬币/露水/当季种子；
     失败按来客造成作物、枯萎或冻住损失。
   - 安抚：支付露水、硬币或仓库作物，稳过；有的来客附带回礼。
4. **具体数值**：
   - 春·蛙雨：赶走成功 +45 硬币 +3 露水 +1 豌豆种，失败踩坏 2 块正在长的地；引水 1 露水；
     忽略踩坏 1 块。
   - 夏·野火：隔离成功 +55 硬币 +4 露水 +1 西瓜种，失败烧掉 2 块成熟作物；浇水 2 露水；
     忽略烧掉 1 块。
   - 秋·熊獾：守夜成功 +70 硬币 +5 露水 +1 稻种，失败搬走 5 个仓库作物；投喂 3 个作物换
     1 颗稻种 +2 露水；忽略搬走 2 个。
   - 冬·巨鹿：硬扛成功 +65 硬币 +6 露水 +1 白萝卜种，失败冻住 3 块地；生火 2 露水 +10 硬币；
     忽略冻住 2 块。
5. **窗口结束未处理**：按该来客的"忽略"损失结算一次，记日志；状态标记为已结束，
   不会每个 tick 重复扣。
6. **状态** `season.json` 的 `omen: { day, season, id, start, end, resolved, choice, result }`；
   `day` 是季节开始日，`start/end` 是随机窗口；`resolved` 后不重复弹。
7. **只给主人**：访客/看田模式不显示来客卡；来客不进入 LAN 协议，不影响邻居。
8. **掷骰注入**：用 `farmRandom`；测试可固定成功/失败。

## 考虑过的选项

- **实时 boss（HP/倒计时/桌面巨兽）**：最有饥荒味，但需要新实体、寻路、动画、LAN 同步、
  离线处理；v1 范围爆炸；否决。
- **每天固定出现**：1 天 1 季会让来客变成每日打卡，和每日节日抢注意力；改为随机 3 小时，
  只占一天的一部分。
- **四个来客一起上，但不加新地块状态**：野火/巨鹿只能写成枯萎，冬天没有区别；
  最终补 `frozen` 状态（ADR-0023）。
- **硬惩罚（毁一块地/全枯）**：idle 玩家离线回来发现地没了，挫败感太强；否决。
- **纯奖励、无代价**：来客变成又一个节日，失去"季候压力"；否决。

## 后果

- 季节有了"正向节日 + 偶发压力"两层；玩家在窗口内会多看一眼农场。
- 来客窗口随机且只有 3 小时，错过会按忽略结算；损失可见、有限，不删档。
- 守卫/雇工/仓库被重新使用，没有新增战斗系统；四个来客复用同一张卡的结构。
- 临时守卫只属于一次来客结算：不进入合同、不占雇工位、不跨机；这样不用把单雇工模型扩成多雇工。
- 来客是本地事件，LAN 邻居看不到；如果以后要做"邻居协防"，需要新的协议与权限，
  不在本 ADR 范围内。
- 读系统时间可以"跳过"秋天，但也会跳过节日/作物；这是本地时钟游戏，不做防作弊。
