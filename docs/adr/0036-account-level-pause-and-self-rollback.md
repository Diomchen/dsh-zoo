# ADR-0036：暂停与退出归账户自己，房主不再有全场开关

- **Status:** accepted（2026-11-18，票 112）
- **Supersedes:** ADR-0032 决定 5 里「市场闸门 `off` 由房主统一关闭」那半句
- **Related:** ADR-0035（档位下放到账户）

## 背景

票 98 把「灰度三档」做成市场级的开关，`off` 是房主手里的全局闸门：房主按一下，
所有人的新仓、挂单、结算报文一起停。`futures-rollback` 同样是全场动作：房主强平
本地 + 所有远端仓位，把每个人的托管余额退进**房主自己的农场**，再给对方记一条
`pending`。

这两件事在单机上没问题，在局域网里就变成了「谁当房主，谁手里有一把能按住所有人的
开关」。用户的原话是：

> 不对，这个规则要改啊，怎么可能我自己不想玩真实硬币不给切呢

档位已经按 ADR-0035 下放了；这一张票把最后两件「别人的按钮能影响我」的事一起拆掉：

1. 房主关市 = 全场停摆；
2. 房主回滚 = 替全场退款，钱还落进房主农场。

## 决定

1. **暂停是账户自己的**。每个账户有 `paused` 字段；暂停后只拒绝**这个账户**的新仓与
   新挂单（`paused`），已有的仓、余额、挂单都不动；平仓、撤单、转现货、提现一律放行
   （它们是减风险的动作）。没有全局关市。
2. **老入口保留、语义改变**。HTTP 动作 `futures-mode{mode:'off'}` 仍然能用，但等价于
   `futures-pause{paused:true}`：只停自己。`mode` 字段继续存在（settle 里回传），只为
   兼容旧客户端，不再拦截任何人的动作。
3. **退出只退自己**。`futures-rollback` 只强平本地仓位、只退本地托管余额、只把本地账
   标 `disabled`。peer 的账在房主那台，peer 调这个动作回 `not-owner`，提示先平仓再提现。
4. **报文新增 `futures-pause { paused }`**（peer → 房主申报），settle 增加可选
   `paused` 字段回传。缺失视为 `false`；非法值整包拒。
5. **审计**：暂停与继续都写一条 `kind:'mode'` 流水（`note` 为 `off` / `live`），和切档
   共用一种流水，窗口的「最近成交」里看得到。
6. **房主的职责收窄为记账**：排序（谁是房主）、记账（余额、撮合、强平）、广播
   （settle）。他不再拥有「停别人」「退别人钱」的能力。

## 考虑过的选项

- **保留全局关市，只加「申请开市」**：还是要看房主脸色，没解决根本问题，否掉。
- **房主关市时自动改选新房主**：选举逻辑会抖（谁都能通过「关市」把自己变成前房主），
  而且不解决回滚越权，否掉。
- **把回滚拆成「自退」+「房主清算」两个动作**：多一个动作就多一条要维护的权限路径，
  而「房主清算」本来就不该存在，否掉。
- **`futures-mode` 直接删掉**：老脚本和老测试会一起断，且 settle 里的 `mode` 字段还有
  兼容意义，改成「别名」比删掉便宜。

## 后果

- 好处：任何一个人的按钮只影响自己。房主掉线或作恶，最多让市场停摆（没人记账），
  不会让谁的钱消失、也不会让谁被迫停手。
- 代价：**没有全局急停**。真出问题时（比如有人写出刷币脚本），只能各自暂停、各自退出，
  房主能做的只有不广播——这一点写进 README 的「已知限制」。
- 代价：`mode` 字段变成「只写不读」的兼容字段，读代码的人容易误以为它还是闸门，
  所以在 `CONTEXT.md` 里明确写了「暂停才是账户自己的开关」。
- 迁移：旧 `futures.json` 没有 `paused` 字段，读盘时补 `false`；旧 peer 不发
  `futures-pause`，房主按 `false` 处理，互不影响。

## 未定

- 房主长期掉线时，托管账本仍然只在他那台机器上。真正的解法是 ADR 之外的另一张票
  （账本快照随 settle 广播，换房主时用 `(epoch, seq)` 最大的那份重建），还没做。
- 是否给「暂停」加自动过期（例如 24 小时后自动恢复），现在没有，也不打算加。
