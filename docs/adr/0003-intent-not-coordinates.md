# 只同步动作意图，不同步坐标

## Status

accepted

## 背景

让邻居的宠物在我屏幕上走动，有两条路：把它的坐标逐帧发过来；或者只告诉对方"它现在在干什么"。

## 决定

协议只传**动作意图**，而实现里真正上网的意图只有一项：**动作名**（取自 `dsh-pet` 的动画池），在 `heartbeat` 和 `visit-request` 里都是 `anim`。坐标永远不出本机——每台机器给自己的宠物跑物理，访客在本机也由本机模拟走动。

早期设计里还写过"朝向"和"是否正在被拖拽"，实现时删掉了：

- **没有消费者**：客厅只按动作名选一段素材播放；访客走成什么样由本机决定，没有哪一帧渲染需要朝向。
- **拖拽是纯本机交互**：它描述的是“我这台机器的用户正在怎么操作”，按“坐标永不过网”的同一原则，没有必要把本机交互状态广播出去。

## 考虑过的选项

- **坐标同步**：两边看起来逐帧一致，但等于让两套物理引擎互相拉扯；局域网 10ms 抖动就会让影子抽搐，而且对方机器一卡，本机也跟着卡。

## 后果

- 抗延迟：丢一个心跳只是少一帧动作，不会穿模。
- 两边看到的轨迹不一样——这是有意的，不是 bug，写进协议文档避免以后有人"修"它。
- 访客的位置由本机决定，所以"它在我这儿自己找了个角落待着"是合法状态。
- 协议里没有朝向/拖拽字段；以后要加，必须像 `visit-deny` 的 `reason` 一样先有明确消费者，并按白名单字段处理。
