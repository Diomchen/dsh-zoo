# ADR-0031：盘口作物清单跟随作物目录

**Status:** accepted
**Date:** 2026-11-17

## Context

SPEC v10 与票 81 把盘口固定成番茄 / 胡萝卜 / 南瓜三种。但农场作物目录是运行时数据
（`src/farm-rules.js` 的 `CROPS`，可由跨机目录同步扩充，当前已有 10 种）。用户明确要求：
「只要有新的作物添加，就会有新的品种」——盘口不能比农场少作物。

## Decision

1. 盘口的作物清单不再写死，改为 `boardCrops()`：当前作物目录里**有有效底价**的全部作物，
   顺序沿用目录顺序。
2. 所有依赖作物清单的地方（图表 payload、窗口页签、下单校验、`trading-digest` 的
   `positions[].crop` 白名单、排行榜 chips）都走同一个函数；未知/坏底价作物一律忽略。
3. 窗口的作物条随数量增长：单行横向滚动（左右箭头 + 滚轮 + 键盘），不换行、不撑高。
4. payload 体积（票 90 修订）：一包只带**当前选中作物**的四个周期图与风向；
   其余作物切过去时走 `trading-charts { cropId }` 按需拉取，窗口缓存最近 4 种。
   `limits.crops` 仍然列完整目录，作物条与下单白名单不跟着缩水。
   为什么必须改：一次全发在 15 种作物时归一化后约 308 KiB，超过 helper 单行
   256 KiB 的 IPC 上限，`encodeMessage()` 返回 null——窗口根本打不开，还被误报成
   「桌面层没在运行」。

## Consequences

- 新加作物（含跨机同步来的）重启/重载后自动出现在盘口，不需要改代码。
- 一包的体积与作物总数基本无关：15 种约 17 KiB、40 种约 18 KiB（helper 白名单之后），
  目录继续长也不会撞上 IPC 单行上限；代价是切到没看过的作物要走一次 `trading-charts`。
- 指令编不出来/发不出去时宿主报 `board-send-failed` 并留一条带尺寸的诊断；
  「桌面层没在运行」（`desktop-off`）只留给真的没有桌面层的情况。
- 旧邻居的 `trading-digest` 里出现本机不认识的作物：整包按协议白名单丢弃（与旧口径一致）。
