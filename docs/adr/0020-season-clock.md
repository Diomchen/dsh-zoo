# 季节时钟：1 个本地自然日 = 1 季，4 天一轮

## Status

accepted（2026-11-13）。决策来自用户："1天1季，4天一轮"。
实现票 63 / 68；玩家文档见 SPEC v8。

前情：[ADR-0016](0016-farm-economy-federated.md)（农场经济联邦）、
[ADR-0019](0019-runtime-crops-over-lan.md)（运行时作物）。

## 背景

农场此前没有时间感：作物只按 `plantedAt + growMs` 生长，今天和下周打开是同一幅画面。
用户要"四季变换和季节事件"，并明确压缩为 **1 天 1 季、4 天一轮**。

星露谷的 28 天/季、112 天/年不能直接搬：它的 6 天作物在一季里约 4.7 轮；dsh-zoo 的
6 小时作物在 24 小时里约 4 轮。若把一季拉成 7 天，6 小时作物会有 28 轮，节奏过密，
且玩家一周才看到一次换季。1 天 1 季是"压缩后的同一密度"，不是偷懒。

约束：

- 不能按 DSH 启动时间算季，否则重启就换季，作物会莫名枯萎。
- 不能把季节写进 `farm.json`，否则改系统时间/换时区会留下不一致的存档。
- 不能把季节同步到 LAN：每台机器的本地日不同，邻居的节日/来客不该互相污染。
- 旧存档必须能直接打开；没有 `season.json` 也要能算出今天。

## 决定

**季节是纯函数算出来的，不落存档；切换点是本地 00:00。**

1. `SEASON_ORDER = ['spring','summer','autumn','winter']`，锚点
   `SEASON_ANCHOR = '2026-10-26'`（本地日，春的第一天）。
2. `seasonAt(now)` 用本地日期分量算"第几天"，`start` = 当天 00:00，`end` = 次日 00:00；
   返回 `{ id, name, emoji, start, end, remainingMs }`。不返回 `day` / `daysLeft`。
3. `seasonSegments(from, to)` 把任意区间切成交替的季节段；离线生长按段算，跨午夜不会把
   整段都算成旧季。最多保留 64 段，防止极长离线把循环撑爆。
4. 本地日 key 用 `seasonDayKey(at)`；`season.json` 的 `event.start` / `omen.start` 都用它，
   `start` 变了就重置。
5. 季节只影响**本地农场**：作物表、生长系数、枯萎、节日、来客。LAN 协议不加字段；
   邻居的农场仍按它自己的季节算，看田看到的是它的地块状态，不是它的节日。

## 考虑过的选项

- **按 DSH 启动时间算**：重启就换季，玩家无法预期；否决。
- **把季节写进 `farm.json`**：需要迁移、需要处理改系统时间；而且"今天是什么季"本来就能算，
  存了反而多一个会不一致的字段；否决。
- **7 天 1 季**：作物轮次过密，且一周才换一次；与用户明确的"1 天 1 季"冲突；否决。
- **28 天 1 季（照搬星露谷）**：dsh-zoo 的作物最长 12 小时，28 天里会收 56 轮，经济爆炸；否决。
- **用 UTC 切日**：中国玩家会在早上 8 点换季，体感不对；用本地 00:00；否决 UTC。

## 后果

- 改系统时间/时区会改季节；这是本地时钟游戏的正常代价，写进 README 的已知限制。
- 测试必须注入 `farmNow`，不能依赖真实 `Date.now`；`seasonSegments` 的边界用例要覆盖跨月/跨年/闰年。
- 离线跨午夜时，作物可能在"最后一次 tick"和"现在"之间枯萎；`#settleLoad` 先按季比较再补生长，
  避免"先长后枯"或"枯了还长"。
- 季节不占存档字段，老存档零迁移；`season.json` 只存节日/来客，损坏可丢。
- 未来若要做"季节长度配置"，只需改 `seasonAt` 的周期常量；调用方不感知。
