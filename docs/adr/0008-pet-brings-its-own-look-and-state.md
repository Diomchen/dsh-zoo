# 宠物自带外观与状态，local-pet 只做传输与画布

## Status

accepted

## 背景

[ADR-0001](0001-bridge-dsh-pet-not-fork.md) 把 dsh-pet 当素材源，后果写得明白：
「素材是按名字对齐的：两边都装了同一个 dsh-pet 才有同一批动画。」

这在一个插件、一个局域网里够用。但用户要的是：**以后别人用别的桌宠插件，他的宠物也能来串门**。
如果每来一个新插件就往 local-pet 里打包一套素材，包会无限长，而且永远慢一步。

用户还明确了一条边界：**local-pet 只提供联机**。宠物的外观、动作、行为、监控本机 DSH，
都是宠物插件自己的事；local-pet 不实现、不接管、不要求对方改代码。

一个实现事实支持这个方向：DSH 的 webServer 只监听 `127.0.0.1`（本机 `lsof` 确认），
邻居访问不到 `/dsh-pet-7340/thumb/...`。所以「让对方来我的 DSH 路由拿素材」走不通，
素材服务必须由 local-pet 自己开在局域网上。

## 决定

**宠物内容归宠物插件，传输与画布归 local-pet。**

一次串门带三样行李：

1. **外观包**：一张清单（我是谁、有哪些动作）+ 动作的 WebM 文件。清单和文件都留在宠物自己家里。
2. **当前动作**：一个自由字符串（如「写代码」），可带一个可选的语义标签（`working` / `eating` /
   `sleeping` / `idle` / `other`）。
3. **一句话**：可选气泡，纯文本、限长；带一个过期时刻，过期就不再显示。

具体规则：

- **拉取，不推送**。对方起一个只读素材服务；接收方按需拉清单和动作文件，拿到就缓存。
  视频本体永远不进 UDP 心跳或串门报文。
- **动作 id 自由**，语义标签固定小表。桌面认识动作名就播对应素材，不认识就看语义标签，
  再不行画通用小人（名字 + 颜色 + 一个中性待机）。
- **气泡跨端默认开**，纯文本、限长、带过期时间；不渲染对方的 HTML/Markdown。
- **协议 v1 加可选字段，不升版本**：`skin` / `action` / `semantic` / `say` 都是可选的；
  旧版本解析时丢弃未知字段，新版本缺字段时退回 `anim` 和老行为。
- **素材服务是 local-pet 自己的**：绑 `0.0.0.0` 的独立 HTTP 端口，beacon 广播这个端口；
  只读、只暴露素材目录、只接受 WebM、限大小/超时、校验 hash。
- **monitor 不跨端**。宠物插件在自己机器上监控 DSH、决定动作；跨端只传「我现在是什么状态」。
  local-pet 不监控 DSH，也不跑对方的行为代码。

兼容梯度（详见 [SPEC v3](../../.scratch/local-pet/SPEC-v3.md)）：

- **L0**：只报动作名（dsh-pet 现状）→ 本机同名素材，没有就通用小人。
- **L1**：带清单和素材地址 → 完整外观。
- **L2**：带语义标签 → 连素材都没有时，通用小人也能表达「在干嘛」。

## 考虑过的选项

- **继续按名字对齐，只支持 dsh-pet**：最省事，但用户要的「别人家的宠物也能来」永远做不到。
- **每个新插件打包一套素材**：包无限长，且永远慢一步；用户已明确否掉。
- **串门时把视频推过来**：不依赖对方开服务，但 UDP 不适合大包，缓存和隐私都更难；
  只作为 L1 不可用时的降级（当前不做）。
- **支持 GIF / Spine / Live2D 等通用动画格式**：那就是「通用桌宠播放器」，不是「串门插件」；
  明确 out of scope。格式不认就画通用小人。

## 后果

- 多了一个跨机 HTTP 端口，也就是多了一个攻击面：只读、白名单、限大小、超时、hash 校验、
  只连私网地址，缺一不可。坏的一个访客不能影响其他访客和串门本身。
- 素材缓存会占磁盘，要有上限和清理；缓存只服务「对方在线期间」的访客，对方离线时访客本来就会走。
- 协议多了一组可选字段，要保证旧版本收到新包不崩、新版本收到旧包能降级。
- 动作 id 自由意味着「同名不同动作」可能撞车：以清单为准，清单里没有的名字不猜。
- 这是 local-pet 第一次从「dsh-pet 的桥」变成「一个开放的小标准」。标准别人愿不愿意跟，
  是产品问题，不是技术问题；技术侧保证「不跟也能降级」。
