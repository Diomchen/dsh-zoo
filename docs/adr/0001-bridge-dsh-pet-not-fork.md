# 桥接 dsh-pet，不 fork 它

## Status

accepted

## 背景

这台机器上已经装着第三方插件 `dsh-pet@0.3.8`：它负责宠物的外观（106 段 VP9-alpha WebM）、物理、拖拽投掷、投喂、对话，并且对外暴露一套 HTTP 接口（`/state` 长轮询、`/anim` 点播、`/broadcast`、`/thumb/<素材根>/<动画名>`）。核心 DSH 没有任何宠物概念。

我们要的是"联网"，不是"宠物"。外观和动画是这个项目里最贵的部分，而它已经做完了。

## 决定

本插件不拥有宠物，只做**桥**和**影子**：

- 本地宠物仍然是 `dsh-pet` 那只，本插件不接管它的渲染、不写它的配置。
- 邻居的宠物由本插件自己画在客厅浮层里，是一具**影子**：从对方同步"动作意图"，在本机复用同一套素材重放。
- 与 `dsh-pet` 的全部耦合收敛在一处：一个读它状态、借它素材的适配层。这一层坏掉时客厅退化成一个带名字的色块，而不是白屏。

## 考虑过的选项

- **完全自建宠物**：外观、物理、动画要从零做一遍，成本最高，且用户已经习惯了现有的那只。
- **fork `dsh-pet` 加"远端宠物"**：能让访客成为一等公民，但从此每次上游升级都要合一次 fork，长期债最重。

## 后果

- 依赖一个第三方包的**未承诺 HTTP 接口**。它升级可能坏。因此适配层必须薄、必须有降级路径，且不把它的数据结构抄进协议。
- 素材是"按名字对齐"的：两边都装了同一个 `dsh-pet` 才有同一批动画。协议只传动画名，不传素材本体；对不上就降级。
