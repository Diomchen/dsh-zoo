# 出远门

> 状态：设计定稿（v0.2）。数值按三轮评审定案，决策与取舍见
> [ADR-0039](adr/0039-expedition-burns-coins.md)。改数字前先读那一篇的「决定」。

地买满 50 块之后，硬币只剩三个出口：买种子（一天几十）、雇工（一天不到 30）、盘口保证金
（不销毁，只是换个地方放）。一天进账 2.8 万，开销不到 1,000，于是硬币只能堆到 100 万上限
然后被静默截断。

**「出远门」是一个把硬币换成故事的系统**：交一笔盘缠，宠物出门走几段路，每段捡一件特产；
你可以见好就收，也可以赌下一段。硬币在这条路上是**净烧**的——盘缠不退，特产不能卖钱。

## 为什么不是别的

| 方案 | 硬币去哪了 | 为什么不做 |
| --- | --- | --- |
| 盘口加杠杆 | 邻居之间转移 | 已经是印钞机（PnL 按模型价结算），再加就通胀 |
| 期货 | 手续费烧 90% | 通道坏着，且日额 5,000 名义，量级太小 |
| 红包 | 转给邻居 | 是转移不是销毁，且一天上限 600 |
| 功德碑 | 纯销毁 | 一次性，没有第二次点开的理由 |
| 赌石摊 | 纯销毁 | 与盘口同质（押一笔、看随机、按倍率结算），且极品要能变现才有意义 |
| **出远门** | **盘缠烧掉 80.5%–89.5%** | 可重复、有随机、有收集、有社交展示 |

## 一次出门长什么样

1. 点「出远门」，选路线（后山 / 废矿 / 老铁路 / 雾岭），付盘缠。
2. 宠物进入 `away` 状态出门（和串门、打工互斥，看家失效）。
3. 每段 **走路 20 秒** → 掉战利品（1 件特产 + 一笔硬币）→ 报下一段危险度 →
   **20 秒决策窗**：你选「继续」或「见好就收」。
4. 继续：走下一段；段数走满自动回家。
5. 翻车：掷骰失败，特产随机丢一半，硬币按已走段数照给，立刻回家。
6. 回家结算：特产进陈列架、图鉴点亮、旅行日志留在农场页，邻居串门能看见。

**关掉窗口也继续走**：计时是真实时间，缩到托盘、切到别的窗口都不影响。
决策窗超时没点，按「见好就收」处理——不靠挂机拖住玩家。

一趟 2–5 分钟，一天想刷几次刷几次——**但每刷一次就烧掉一笔盘缠**。

## 状态机

```
idle ──start(route)──▶ walking(leg=1, loot=[], until=now+20s)
                          │
         ┌────────────────┼──────────────────┐
         │ 到点：掉东西    │ 决策窗超时        │ back（见好就收）
         ▼                ▼                  ▼
   deciding(20s)      home(全额)          home(全额)
         │
         ├── 继续 ──▶ walking(leg+1) ── 走满段数 ──▶ home(全额 + 通关)
         └── 翻车 ──▶ home(loot 减半)
```

- `walking` 与 `deciding` 都由 `expedition-store.tick(now)` 推进，纯函数决定状态迁移；
  写盘只在状态真的变化时发生。
- `away` 期间：不能串门、不能接打工、不能被派去打工；看家失效（守卫按现有公式归零）。
- 进程重启：从 `expedition.json` 读回 `run`，按 `until` 与当前时间**只推进一个节点**
  （walking → deciding，或 deciding 超时 → home），不补掷骰、不补多段——关机不能刷钱。
- 一趟没结束不能开第二趟（`already-away`）；结束后无冷却，可立刻再开。

## 路线

| 路线 | 盘缠 | 段数 | 基础危险 | 每段 +危险 | 特产 | 解锁 |
| --- | --- | --- | --- | --- | --- | --- |
| 后山 | 500 | 3–4 | 5% | +3% | 8 件（5 普 / 2 稀 / 1 珍） | 默认 |
| 废矿 | 3,000 | 4–5 | 8% | +3% | 8 件（4 / 3 / 1） | 走过 3 次后山 |
| 老铁路 | 15,000 | 5–6 | 10% | +3% | 8 件（3 / 4 / 1） | 图鉴集齐 8 件废矿 |
| 雾岭 | 60,000 | 6–7 | 12% | +3% | 8 件（2 / 4 / 2，含 2 件传说） | 图鉴集齐 8 件老铁路 |

段数在区间里随机（例如后山每趟掷 3 或 4）。

**为什么是这几档**：后山 500 是「随手玩一把」；雾岭 60,000 是「认真烧一次」，大约等于两天收入，
不至于一把梭光但会心疼。四档首尾差 120 倍，刚好覆盖从「试玩」到「大额销毁」的区间。

危险度默认只显示「低 / 中 / 高」三档 + 已走段数；买了提灯才显示精确百分比。

## 战利品

每段先掉东西，再报危险：

- **硬币**：`round(盘缠 × 3%)`，实际值再乘 `rand(0.75, 1.25)`。一趟走满的硬币回报是盘缠的
  9%–21%（段数越少越靠下限），平均 15% 上下。
- **特产**：按该路线的掉落表抽 1 件，同一趟不重复（抽到已有的就重抽；抽满 8 件则改为硬币 ×2）。

| 路线 | 特产（id） | 稀有度 |
| --- | --- | --- |
| 后山 | 草药 herb、怪石 oddstone、松果 pinecone、羽毛 feather、蘑菇 mushroom | 普通 |
| 后山 | 陶片 shard、山楂 hawthorn | 稀有 |
| 后山 | 鸟蛋 egg | 珍稀 |
| 废矿 | 矿石 ore、煤块 coal、齿轮 gear、兽骨 bone | 普通 |
| 废矿 | 旧工具 oldtool、锈钱 oldcoin、晶簇 crystal | 稀有 |
| 废矿 | 月光石 moonstone | 珍稀 |
| 老铁路 | 铜铃 bell、信号旗 flag、铜钥匙 key | 普通 |
| 老铁路 | 怀表 watch、车票 ticket、站台牌 sign、徽章 badge | 稀有 |
| 老铁路 | 行李牌 tag | 珍稀 |
| 雾岭 | 雾灯 mistlamp、白鹿角 antler | 普通 |
| 雾岭 | 云纹佩 cloudjade、星砂瓶 starsand、雾凇枝 frostbranch、银哨 whistle | 稀有 |
| 雾岭 | 石敢当 stele、山神印 seal | 传说 |

稀有度只影响抽取权重（普通 30 / 稀有 12 / 珍稀 4 / 传说 1），不影响价格——**特产不能卖钱**，
这是整个系统的地基：能卖就变成刷钱，不能卖才是收藏。

## 钱怎么算

以期望段数（3.5 / 4.5 / 5.5 / 6.5）走完一趟为例：

| 路线 | 盘缠 | 期望段数 | 每段回币 | 硬币回报 | 净消耗 | 净烧比例 |
| --- | --- | --- | --- | --- | --- | --- |
| 后山 | −500 | 3.5 | 15 | +52 | −448 | **89.5%** |
| 废矿 | −3,000 | 4.5 | 90 | +405 | −2,595 | **86.5%** |
| 老铁路 | −15,000 | 5.5 | 450 | +2,475 | −12,525 | **83.5%** |
| 雾岭 | −60,000 | 6.5 | 1,800 | +11,700 | −48,300 | **80.5%** |

越往后净烧比例越低——因为跑得越远，捡得越多。想烧得快就多刷后山，想赌大件就上雾岭。

失败（半路翻车）时战利品减半：特产随机丢一半，硬币按已走段数照给——**盘缠永远不退**。
所以翻车那趟的净烧比例只会更高，不会更低。

## 升级

v1 只有两样，都是「一次性、看得见」的东西：

| 东西 | 价格 | 作用 |
| --- | --- | --- |
| 提灯 | 10,000 | 决策窗显示每段的实际危险度（默认只显示「低 / 中 / 高」） |
| 陈列架格 | 5,000 / 格 | 默认 8 格，最多 32 格；全开 120,000 |

**砍掉的**：背包三档（一条路线只有 8 件、一趟最多 7 段，不会真卡）、靴子（把 20 秒变 10 秒，
卖的是等待时间不是内容）、护身符（500 对 60,000 的雾岭等于花 0.8% 免掉翻车，会把紧张感抹平）。

## 实现落点

| 东西 | 位置 |
| --- | --- |
| 规则（纯函数，不碰 IO，参数传 `now` / `rng`） | `src/expedition.js` |
| 状态与落盘（json 读写、种子 RNG、损坏修复、快照） | `src/expedition-store.js` |
| 状态文件 | `<dataDir>/expedition.json`（`{ run, shelf, codex, logs, upgrades }`） |
| 动作 | `expedition-open` / `expedition-start` / `expedition-step` / `expedition-back` / `expedition-shelf` |
| 快照 | `state.expedition = { run, shelf, codex, upgrades }` |
| 窗口 | `desktop/expedition.html` + `expedition-open` 打开 |
| 互斥 | 复用 `room.outboundWork()` / `working()` / `outboundVisit()` 那套门控；`away` 期间 `hire` / 串门报 `already-away` |
| 扣币/回币 | `farm.spendCoins(qty)` / `farm.addCoins(qty)`（`src/farm.js:1082`、`src/farm.js:1087`，都返回 Promise） |
| 时钟 | service 的秒级 tick 调 `expedition-store.tick(now)`；窗口只读快照 + 发动作 |

动作语义：

| action | body | 返回 |
| --- | --- | --- |
| `expedition-start` | `{ routeId }` | `{ ok, run }`，扣盘缠，写 `run.startedAt` |
| `expedition-step` | `{}` | `{ ok, run, leg: { loot, dangerNext } }`，推进一段；翻车则 `run.ended = 'failed'` |
| `expedition-back` | `{}` | `{ ok, settled: { spent, coins, items, shelf } }` |
| `expedition-shelf` | `{ slot? }` | 开格子 / 移动陈列 |
| `expedition-open` | `{}` | 打开窗口（不改变规则状态） |

错误码：`already-away`、`no-route`、`not-enough-coins`、`not-walking`、`locked`。

随机：`runId`（`start` 时生成）做种子，`hash(runId, leg)` 派生每段的掷骰与掉落——同一个 run
重放结果一致，出了问题能对着日志复算，也不会被 `Math.random()` 打乱。

## 平衡校验

- **烧掉当前 37 万**：约 826 趟后山（每趟 −448），或 7.7 趟雾岭（每趟 −48,300）。
  不会自己消失，但真想花就有地方花。
- **一天的销毁上限**：后山一趟约 2.5 分钟（4 段 × 40 秒），100 趟 ≈ 44,800 ≈ 1.6 天收入。
  高频刷后山是主力销毁，雾岭是「一次性大额」。
- 硬币回报永远小于盘缠（15% 上下），所以不存在「刷出正期望」的路线；
  特产不可售，所以不存在「刷特产换钱」。

## 不做

- 不做邻居联机（v1 只在本机跑，特产不跨设备同步）。
- 不做特产交易 / 拍卖（会立刻变成刷钱）。
- 不做特产塞红包（v2；数据结构先留 `giftable: true`）。
- 不做限时活动（先看常规循环的数据）。
- 不做「宠物受伤」的惩罚系统（失败已经丢了半趟，再加一层会劝退）。
- 不做连刷冷却 / 每日次数上限（冷却会掐死唯一的高频销毁入口）。
- 不重做硬币 1,000,000 上限（见下）。

## 已知问题

- 硬币到 1,000,000 上限后，农场收入在 `src/farm.js:1912` 的
  `Math.min(MAX_COINS, before + qty)` 处被静默截断。这轮不修：它牵动盘口、期货、
  红包的所有换算，留单独一票。
