# 1.12.1：窗口里的按钮都点得动了

1.10.0 加的「切到真钱 / 切到纸面」、1.11.0 加的「全部转」、1.12.0 加的「暂停交易 / 退出」，
在窗口里点了都没反应——不是账本拒绝，是窗口自己的白名单把动作拦在门口，连一句报错都没有。
这一版把三道门补齐，并加了一条回归测试：以后新增动作，只要忘了登记，测试就会红。

## 症状

- 顶栏的「切到真钱」「暂停交易」「退出」、持仓表头的「全部转」，点下去什么都没发生：
  按钮不闪、不弹提示、状态不变；用 HTTP 手动发同一个动作却是好的。
- 关掉窗口重开也一样，因为问题不在窗口实例，而在窗口加载时注册的那份白名单。

## 原因

窗口到宿主之间有两道白名单：

1. `desktop/shared.js` 的 `FUTURES_SUBMIT_ACTIONS` —— 「窗口能表达哪些动作」；
2. `desktop/futures-preload.js` 的 `FIELDS` —— 「每个动作允许过桥哪些字段」。

第一道跟着功能走，第二道是手写的，1.10–1.12 三次加动作都只改了第一道。
preload 遇到没登记的动作会 `return null`，`submit()` 于是返回 `false`、一个字节都不发。
窗口那边以前不看返回值，所以按钮就成了「死按钮」。

## 修复

- `desktop/futures-preload.js` 补三个动作：
  - `futures-account-mode { accountMode }`（1.10.0 切档）
  - `futures-pause { paused }`（1.12.0 暂停/继续）
  - `futures-convert-all { positions }`（1.11.0 全部转；只收 1–8 笔 `{ id, lots }`，
    张数必须是 1..100000 的整数，别的形状整条拒——和宿主侧 `bad-positions` 同一套口径）
- `desktop/futures.js` 所有提交改走一个 `send()`：拿不到接收就弹一句
  「这个操作发不出去：窗口的动作白名单里没有它，更新插件后重开窗口试试。」
  往后同类漏登记至少是「看得见的错」，不再是「点了没反应」。
- 新测试 `test/futures-preload.test.js`：用 `vm` 把 preload 跑起来，逐个动作调 `submit()`，
  断言 `shared.js` 的 `FUTURES_SUBMIT_ACTIONS` 一个不少地被 preload 接受；再验证字段白名单
  （多余的 `balance`、`entry` 不过桥）与「全部转」的形状校验。

## 顺手

- 拒绝原因不再被吞掉。宿主回的是 `{ ok, notice, code }`，窗口以前只看 `message`，
  于是所有拒绝都显示同一句「没成交，再试一次」——现在先说 `notice`，没给就按错误码兜底
  （`daily-cap` → 「今天的交易额用完了，明天 00:00 重置」、`no-balance` → 「托管余额不够」……）。
- 日额与持仓名义的拒绝文案带上数字：`今日交易额已到上限：上限 5000 名义，已用 3500，
  这笔要 1560，明天 00:00 重置。`——不用自己猜还能下多大。
- 下单预览的「名义」改成真实名义（张数 × 100 × 价）。以前写的是「保证金 × 杠杆」，
  保证金太小、张数被抬到 1 张时会显示成「名义 100 / 保证金 1554」，看着像算错了。
- 新增 [`play-futures.md`](play-futures.md)：给玩家的期货手册——一分钟上手、窗口地图、
  一天的节奏、四档杠杆的保证金/爆仓距离、到期两条路、常见报错的对照表。README 的期货节也加了入口。

## 兼容性

- 协议没变，报文没变，账本格式没变；这一版只动窗口侧。
- 已经开着的期货窗要**关掉重开**才会加载新的 preload。

测试：`npm run check` → 1230 用例 / 1229 通过 / 1 跳过 / 0 失败。
