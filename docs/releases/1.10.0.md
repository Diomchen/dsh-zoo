# dsh-zoo 1.10.0

两件事：**「玩不玩真钱」不再由房主决定，每个账户自己说了算**；顺手把红包从 1.6.5 起
就漏掉的三处接回来了。

- 期货档位下放：ADR [0035](../adr/0035-account-level-futures-mode.md)
- 红包可见性：票 79 补，见本文末「红包：看得见，也翻得到」

## 一、档位下放到账户

### 为什么改

1.9.0 的档位是市场级的：房主切到纸面，网络里所有人都只能玩纸面。实际情况是——邻居里
`deviceId` 排在前面的那台当了房主，它停在纸面，于是在别的机器上想开仓会被 `daily-cap` 拒，
想切真钱又回 `not-host`。

用户的原话：「不对，这个规则要改啊，怎么可能我自己不想玩真实硬币不给切呢」。

### 现在怎么分工

| 谁 | 决定什么 |
| --- | --- |
| 房主 | 只决定**开市 / 关市**：关市时窗口写「期货未开放」，`futures-*` 报文不收不发 |
| 每个账户（含房主自己） | 决定自己玩**纸面**还是**真钱**，随时可切，不用求人 |

- 纸面（`shadow`，缺省）：撮合、盯市、强平、交割全跑，钱只在托管账里动，自己的 `farm.json` 一分不动。
- 真钱（`live`）：充值扣自己的农场硬币、提现加回；手续费与亏空进的是真钱保险基金。

窗口顶栏有「切到真钱／切到纸面」按钮；HTTP 也可以：

```
POST /dsh-zoo/action {"action":"futures-account-mode","accountMode":"live"}
POST /dsh-zoo/action {"action":"futures-account-mode","accountMode":"shadow"}
```

### 两本账，互不交叉

纸面账户的挂单只跟做市商成交，**永远不会吃掉真钱玩家的单**。不然「纸面账户稳定盈利、真钱账户
稳定亏损」会把保险基金抽干——假钱赚真钱是这一版最需要堵的洞。做市商对两本账都扫单，所以任何
时候都有对手价。

纸面账户的手续费不进保险基金、亏空不记欠账（不花真钱基金，也不凭空铸币）。

### 纸面也能正经交易

原来的「影子模式日额 0（只供观察）」取消：纸面账户与真钱账户同样有 5,000 名义日额、20,000 名义
持仓上限，只是数是纸面的。所以「不想玩真钱」终于等于「能玩，但不动真钱」，而不是「不能玩」。

## 二、红包：看得见，也翻得到

从 1.6.5 红包落地起，有三处漏接，对应用户那句「别人发给我的看不到，我发给别人的记录也没有」：

| 漏在哪 | 现象 |
| --- | --- |
| `desktop-pets` 的 `giftsFromSnapshot` 不认 `packet` | 红包卡从来没进过桌面场景 |
| `room` 的 `visitorGift` 把红包降级成字条 | 金额、作物、祝福语全丢；`visit-record` 的 `normalizeVisitGift` 更直接返回 `null`，出门记录里连字段都没有 |
| 农场记录页的 `FARM_LOG_KINDS` 白名单没有 `packet` | 宿主写进 `farm.log` 的红包条目在下发桌面时整条被丢掉，事件/方向/内容三个字段也没留 |

一并修掉的可见性问题：

- 没拆的红包卡不再跟着访客一起消失，改贴在自己宠物旁边，直到拆开或 24 小时退回；
- 红包在 `farm.json` 里单独攒一份 `packetLog`（≤50 条），不跟种下/收获的流水抢位置——自动收菜
  一分钟两条流水，半天就能把红包挤出 200 条的窗口；老文件升级时会把流水里剩下的红包捞进这一份；
- 农场「记录」页顶上钉一块「红包记录」，收到 / 拆开 / 送出 / 退回各一句，流水照旧 100 条。

## 三、兼容性

- 协议版本仍是 1，`futures-settle` 多一个**可选**字段 `accountMode`：老房主不发 = `null`，peer 沿用
  本地选择；新房主回传后以房主为准（换机器也认这个账户）。
- 新增报文 `futures-mode`（peer → 房主，申报自己的档位），旧端不认识时整包丢弃，不崩不回。
- 旧存档里的 `mode: 'shadow'` 仍能读，含义降级为「谁都没开真钱」；房主档位里的 `shadow` 不再是
  一个可选开关，开市即 `live`（是否真钱由各账户自己定）。
- `farm.json` 新增 `packetLog`，老文件读取时自动从流水里补齐，旧字段不变。
- 不需要清 `futures.json`，也不需要清 `farm.json`。

## 四、顺手修的

- `desktop/shared.js` 的 `normalizeFuturesView` 从来没放行 `mode`/`disabled`/`pending`/`dayCap`/
  `dayNotional`/`positionCap`/`peer`/`role`/`hostId`，导致真实窗口里徽章永远画「真钱」、限额行永远是空的。
  现在全部放行（白名单 + 类型校验）。
- 窗口顶栏从「档位下拉框 + 应用」改成「我的档位徽章 + 切换按钮」，房主另有一条「关市/开市」。
