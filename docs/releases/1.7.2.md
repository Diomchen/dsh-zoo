# dsh-zoo 1.7.2

这一版三组修复：入口点击在长时间运行后失效、红包寄不出去/重启丢件、红包发给老版本会静默蒸发。

## 入口点击（桌面宠物 / 右键菜单）

症状：跑久了以后点右键没反应、菜单项也点不动，只能重启插件。

- 渲染端补了「丢 down 兜底点击」：某些机器上分层 overlay 收不到 `WM_LBUTTONDOWN`，只收得到
  `*BUTTONUP`，浏览器永远凑不出 `click`。现在 `pointerup` 发现「只见到松手、没见到按下」时，
  用 `elementFromPoint` 找到目标并补发一次 `click`。
- 弹层矩形（菜单/面板）过期时间从 900ms 放宽到 3s，并在有弹层时每 500ms 补报一次心跳——
  以前菜单开着 3 秒后光标一离开猫身就被判成「窗外」，窗口翻回鼠标穿透。
- 新增矩形看门狗：渲染端连续 4 秒没报矩形就发 probe，3 次叫不醒才重载渲染进程（60 秒冷却）。
- `hit` 事件改为「状态或目标变了就发」，不再只在可交互态翻转时发；冒烟里的悬停断言也因此稳定。

## 红包：寄不出去、重启丢件

- `handleBringPacket` 的回执少了 `item`，上层 `handleBringAction` 读 `added.item.id` 直接
  `TypeError`，于是钱和物都动了、窗口却报「这次操作没有完成，稍后再试」。已补 `item`。
- 背包落盘把红包当成字条写（`kind:'text'` + 空 `text`），重启后变成坏件被丢弃——红包和
  已扣的硬币一起蒸发。现在按 `kind` 分开序列化，红包落 `packet` 字段。
- 空白祝福语曾被判成非法，导致「不写祝福语就整只红包被拒」。现在空白视为「没写」。

## 红包：发给老版本静默蒸发

红包是 1.6.5 才有的能力。更早的版本在 `normalizeGift` 里遇到 `kind:'packet'` 会**整件丢掉**，
串门却照常成功——发件方看到「送出去了」，对方什么都没收到。

- `CAPS` 新增 `packet`，心跳/beacon 一起声明。
- 串门取背包最旧一件时，若它是红包且目标邻居没声明 `packet`，红包**留在背包**，返回
  `packetHeld: true` 并提示「对方版本还不支持红包，这次先帮你留在背包里。」，串门照常进行。
- 结果是：老邻居收不到也丢不了；对方升级到 1.7.2+ 后自动恢复。

已知取舍：1.6.5–1.7.1 的邻居其实能收红包，但没有声明能力，所以也会被扣下；升级即可。

## 兼容性

- 协议只多了一个 cap 名称，没有新包类型；老版本收到 `caps:['raid','look','crops','packet']`
  会忽略多出来的名字，握手不受影响。
- `packet` 能力缺失时的行为是「不发送」而不是「报错」，所以混版本局域网不会互相阻塞。
