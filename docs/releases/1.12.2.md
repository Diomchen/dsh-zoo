# dsh-zoo 1.12.2

日额不再是一刀切的 5,000 名义：账户权益越大，能开的越多。顺带修掉两个「重启之后档位就变了」的落盘问题。

## 日额跟权益走

以前每个账户每天固定 5,000 名义：一张蓝莓（1 张 = 100 单位 × 15 块 ≈ 1,554 名义）就吃掉三成额度，
一天只能开三张；余额几十万的人也被同一把小尺子量着。

现在：

```
日额上限 = max(5,000, 5 × 权益)
权益    = 余额 + 已占保证金
```

- 地板仍是 5,000，新账户第一天的手感和以前一样；
- 权益 20,000 → 日额 100,000；权益 100,000 → 500,000；
- 用权益而不是浮盈：浮盈每 15 秒变一次，额度不该跟着抖；
- 上限每天本地 00:00 归零，和以前一样；持仓名义上限（20,000）没有变。

窗口顶栏的限额行、`GET /dsh-zoo/state` 的 `futures.dayCap` 都按账户实时算，
「今日交易额已到上限」的提示里会写清上限、已用和这一笔要多少。

## 档位与暂停现在会落盘

两个老 bug：

1. `futures.json` 从来没存 `accountMode`，档位只靠 `mode` 反推。按一次暂停（`mode` 变 `off`）
   再回来，账户就变成「纸面」——充值不扣农场、提现不进口袋，看着像赢了其实一分没动。
2. 房主那边的远端账户不存 `accountMode` / `paused` / `disabled`。房主重启一次，
   邻居就自动恢复成「纸面、没暂停、没退出」。

现在这两个都写进盘上：重启、暂停、继续之后，账户还是你自己选的那个档位。
老入口 `futures-mode { mode }` 仍然能用，但语义变成「把这个账户自己设成那个档位」——
只翻闸门不改档位的写法已经不存在了。

## 兼容性

- 协议没有新增字段：`dayCap` 只是视图里的数字变大，`futures-mode`/`futures-pause` 的形状不变。
- 老存档照常读：没有 `accountMode` 的按 `mode` 反推，没有 `paused` 的当成没暂停。
- `futures-mode { mode: 'off' }` 仍旧只暂停调用方自己（1.12.0 起房主就没有全场开关了）。

## 测试

`npm run check`：1,232 个用例 / 1,231 通过 / 1 跳过 / 0 失败。

新增用例覆盖：日额地板与放大（`dailyNotionalCapFor` 四个点）、用满即拒且拒单不累计、
大小账户各算各的、档位与暂停重启后不丢。
