# dsh-zoo 1.13.1

这一版只动期货，盘口和图都不碰。四件事：按钮真的会动了，账目对得上了，提现能到账了，
切档不再被别人卡住。

## 点了没反应的那几个按钮

- 桌面那一跳的字段白名单从 1.9 起只抄了开平仓用的六个字段，充值、提现、限价挂单、
  转现货、「全部转」、切档、暂停的字段全被丢在路上——所以点了之后什么都不发生。
  现在补齐，这七个动作都真的发得出去。
- 窗口侧也补了一道保险：真发不出去时直说「这个操作发不出去：窗口的动作白名单里没有它，
  更新插件后重开窗口试试」，不再假装成功。

## 切档：你说了算，房主只负责记账

- 档位以本机为准。房主没确认（它可能没升级、或者刚重启把账弄丢了）时，窗口会直说
  「房主还没确认这个档位」，并且本机每 30 秒自动补发一次申报，不用你再点。
- 协议层修了两个报文从来编不出字节的问题：`futures-mode`、`futures-pause` 掉进了兜底分支、
  抛出 `invalid port` 又被吞掉，于是「切到真钱」只在本地记了一笔，房主永远当你是纸面。

## 账要对得上

- **本机账 = 房主账**：房主副本一到，余额、占用保证金、仓位一律以副本为准，本机只留
  审计流水。不会再出现「本机显示 3127.68、房主只认 402.07」这种两个数打架的情况。
- **仓位记开仓时的档位**：切档之后平仓、交割、强平都按仓位自己的档位记账，不再凭空造币，
  也不会把纸面账户的盈亏记进真钱的做市商账。

## 提现：报意图，房主放款

- peer 不再本地扣账（钱本来就不在本机）。现在发一条 `futures-withdraw` 报意图，房主扣账后
  把 `payout` 随 settle 带回来，peer 按 `at` 去重之后才加进自家农场——同一笔重发十次也只加一次。
- 上一笔还没到账时再提会回「上一笔放款还没送到，到了再提。」；撞到 1,000,000 上限会截断并提示。

## 窗口不再被系统弹窗弄没

- `frame:false` + `transparent` 的窗口上，`window.confirm` / `window.prompt` 会弹系统模态，
  窗口看着就像被关掉了。现在全部换成窗内确认条（切真钱、全部转、退出、提现、转现货五处），
  数字输入也在窗内填，Esc 只撤掉确认条，不关窗。

## 报错说人话

- 45 个错误码都有中文句子了。之前窗口只会说「没成交，再试一次」，价格写错和网络抽风长得一样；
  现在失败的动作一律带上具体原因，比如「今日交易额已到上限：上限 5000 名义，已用 3500，
  这笔要 1554，明天 00:00 重置。」

## 兼容性

- 协议新增 `futures-withdraw` 报文与 `settle.payout` 字段，都是可选的；老版本收到会忽略，
  只是老 peer 提现仍会卡在托管里，需要升级到这一版。
- `futures-mode` / `futures-pause` 现在真的会发出去。没升级的那台房主看不懂这两个类型，会当作
  未知报文丢掉，所以窗口那边要继续显示「房主还没确认这个档位」——另一台也升级之后就没了。

## 测试

- `npm run check`：1301 用例 / 1300 通过 / 1 跳过 / 0 失败。
- 顺手修了 CI 在 Linux 上的一条假红：用例结束时 `futures.json` 还没写完，清理临时目录撞上
  `ENOTEMPTY`；现在清理带重试（仓库里其他测试早就这么写了）。
