# dsh-zoo 1.7.1

修农场窗「点了开不出来」：helper 崩过一次之后，右键「农场」怎么点都没反应，只能重启插件。

## 症状

- 早上还好好的，某次 helper 异常退出/被重启后，右键菜单点「农场」没有任何窗口；
- 重启整个 DSH（插件）就恢复，过一阵又复发。

## 原因

「农场窗开着还是关着」由宿主记账：helper 在开关窗时上报 `farm-window-state`。当窗口开着的时候
helper 进程没了（崩溃、超时被看门狗杀掉、重载），宿主手里的 `farmWindowOpen` 停在 `true`；
新起的 helper 一扇窗都没有，但它的去重起点是 `null`，状态「没变化」就不会上报，于是这个 `true`
永远没人纠正。之后每次点「农场」都被当成「再点一次 = 关窗」，窗口自然再也出不来。

## 修复

- `src/desktop.js`：新增 `resetWindowState()`，在**拉起新 helper / helper 退出 / 进程报错 / ready**
  四个点把 `farmWindowOpen`、`boardWindowOpen` 一起清零；`status()` 里 `farmOpen`/`boardOpen`
  改成 `ready && 窗口真的开着`，没就绪的 helper 一律算关着。
- `src/service.js`：`farmWindowOpenNow()` 遇到 `status.ready === false` 直接当关着，不再相信僵尸状态。
- `desktop/main.js`：窗口对象还在但被藏起来时先 `show()` 再 `focus()`；「开着」以 `isVisible()`
  为准，并监听 `show`/`hide`，可见性一变就回报宿主。

跨版本兼容：存档、红包/盘口协议、窗口尺寸都没动，直接覆盖安装即可。重复的 helper 进程重启 DSH 后
会清掉；即使再出现，上面的状态清零也让它们不再影响「农场」开关。

测试：`npm run check` 1044 个用例、1043 通过、1 跳过（新增 3 条回归：helper 退出后窗口状态归零、
未就绪不上报「开着」、未就绪时点「农场」必须开而不是关；顺手把 `package.json` 的 BOM 守卫改成
CRLF 友好，避免 Windows 检出时误报）。
