# SPEC v11 · 期货市场（LAN 多人 · 房主清算）

> 承接 [ADR-0032](../../docs/adr/0032-futures-host-as-clearinghouse.md)。
> SPEC v10 的盘口、v5–v9 的农场/地块/交易所/雇工/露水/季节全部保留；本文只加一层「期货」，
> 不改 `trading.js`，不动农场经济公式。
>
> 量化依据：盘口当前每 50 币 20× 跟提示 ≈ 28,671 币/天，而本机农场累计才 28,569 币
> （见工作区 `zoo-board-1.7.0-review.md` 第九节）。期货要修的就是这个"印钞"缺口。

**Status:** implemented（2026-11-17，票 92–99，见文末「实现」）

**Tickets:** 92–99

## Problem Statement

现在的盘口合约是**对着机器做的**，不是对着人做的：

- 价格是 `(作物, 一根, 一格)` 的确定性公开函数，谁都能本地算出未来路径；风向提示直接读本根自己的未来，实测命中 96.6%，而界面写着 55–68%。
- 零手续费、亏损以保证金为限、20× 下单根强平线 5%，而 30 万根·作物的样本里最坏逆行只有 4.54%——**20× 实际上爆不了仓**。
- 于是"跟提示、上 20×、每根 50 币"是一条稳定的印钞流水线：一天抹平整个农场的累计经济。

同时它没有交易对手：买卖的另一方永远是本机做市商，玩家之间既不对赌也不成交，LAN 只是共用一张同样的图。

玩家想要的是**能经营的市场**：有对手盘、有价差和费用、会真的被强平、有到期日，赚的钱来自别人亏的钱而不是来自公式。

## Solution

新增一层独立的**期货市场（Futures）**，与盘口并存：

- **房主即清算所**：唯一权威账本在房主机器上，其他玩家只发意图、只收结算。
- **每作物一张周合约**：周一 00:00 上市、周五 20:00 到期，1 张 = 100 个作物。
- **公允价锚现货指数**：`现货指数 × exp(OU 偏离)`，OU 是均值回归噪声（σ 0.4%、半衰期 30 分钟、每 15 秒更新）。
- **做市商连续报价 + 玩家挂单**：做市商在公允价两侧各让 0.2% 连续报价；玩家限价单每根（15 分钟）批量撮合一次，价格优先、同价时间优先。
- **交易所托管账户**：钱从农场硬币充进来，与 `farm.json` 隔离，`marginUsed` 冻结；提现原路退回。
- **有成本**：taker 0.1% 名义、价差 0.2%×2、交割 0.1%；费用 90% 销毁、10% 进保险基金。
- **会真的被强平**：强平线 1/杠杆，20× 就是 5%；亏损以保证金为限，缺口先由保险基金补，基金空则记账不追债。
- **每根净额结算**：不逐笔、不按天，一根一条结算报文。
- **结算是盯市，不是到期**：每根收盘按公允价重估一次，浮盈亏入账、入场价改成收盘价，仓位继续持有到玩家平仓或合约到期——周合约要拿得住，强平才有逐 tick 的路径可扫。

## User Stories

1. 作为局域网玩家，我想用农场硬币给交易所账户充值，这样我不用另外造一套货币。
2. 作为局域网玩家，我想随时把交易所余额提回农场硬币，这样赚到的钱能拿去种地。
3. 作为玩家，我想在窗口里看到 15 个作物各自的本周合约和报价，这样我知道能交易什么。
4. 作为玩家，我想看到买一/卖一和价差，这样我知道吃单要付多少成本。
5. 作为玩家，我想看公允价相对现货指数的偏离，这样我判断现在贵还是便宜。
6. 作为玩家，我想做多，这样指数上涨时我赚钱。
7. 作为玩家，我想做空，这样指数下跌时我也能赚钱。
8. 作为玩家，我想选 1×/3×/10×/20× 四档杠杆，这样我能自己决定风险。
9. 作为玩家，我想在下单前就看到"保证金、名义价值、强平价、手续费"四个数，这样我不会误操作。
10. 作为玩家，我想下限价单并让它挂到成交或收盘撤单，这样我不用一直盯着。
11. 作为玩家，我想一键撤单，这样我改主意时不用等。
12. 作为玩家，我想吃做市商的报价立刻成交，这样我不用等撮合。
13. 作为玩家，我想看到我的持仓（合约、方向、张数、入场价、保证金、强平价、浮盈亏），这样我知道自己暴露多少。
14. 作为玩家，我想在浮亏接近强平线时收到窗口内的红色提示，这样我还有机会自己平。
15. 作为玩家，我想手动平仓，这样我能锁定利润或止损。
16. 作为玩家，我想把持仓"转现货"，这样我不经过现金也能拿到实物作物。
17. 作为玩家，我想在到期日看到交割价是怎么算出来的（最后 4 根 15 分钟收盘均价），这样我相信它没被尾盘操纵。
18. 作为玩家，我想在到期时自动现金交割，这样我不用手动处理。
19. 作为玩家，我想看本周成交记录（时间、合约、方向、价格、张数、手续费），这样我能复盘。
20. 作为玩家，我想看到保险基金余额，这样我知道系统兜底还剩多少。
21. 作为玩家，我想看到本周销毁了多少费用，这样我知道这个市场在通缩。
22. 作为邻居，我想看到别人的持仓和本周盈亏（不含余额），这样周榜有意义。
23. 作为玩家，我想在自己掉线重连后拿到正确的余额与持仓，这样我不怕断网。
24. 作为玩家，我想在房主掉线时看到"市场冻结"，这样我知道不是我的单丢了。
25. 作为玩家，我想在房主 10 分钟没回来时被按最后公允价强制平仓并把余额退回农场，这样我不会被永久锁死。
26. 作为玩家，我想在对方版本不支持期货时看到明确提示，这样我不会以为是自己的问题。
27. 作为房主，我想一键开关期货市场，这样出问题能立刻停。
28. 作为房主，我想在影子模式下让整套撮合和结算照跑但不碰真钱，这样我能先对账。
29. 作为房主，我想给单账户设日交易额与持仓名义上限，这样陌生人开小号也刷不爆。
30. 作为房主，我想让订单只认绑定过源地址的设备，这样别人不能冒名下我的单。
31. 作为房主，我想在存档损坏时按空市场运行而不是崩掉，这样农场和盘口不受影响。
32. 作为玩家，我想在下单被拒时看到具体原因（余额不足/超上限/合约已到期/被限速），这样我知道改什么。
33. 作为玩家，我想让同一笔订单重复发送只成交一次，这样丢包重发不会双开。
34. 作为玩家，我想在结算包丢失后自动补齐，这样余额不会停在旧值。
35. 作为玩家，我想看到当前这根还剩多久收盘，这样我知道撮合什么时候发生。
36. 作为玩家，我想在下单界面看到"这笔最多亏多少"，这样我能对照自己的硬币。
37. 作为玩家，我想让 1× 仓位永远不强平，这样长期持有不会被噪声扫掉。
38. 作为玩家，我想在保证金不足维持时被强平而不是被追保，这样规则简单可预期。
39. 作为玩家，我想让强平按触发价顺序执行，这样极端行情下结果可复现。
40. 作为玩家，我想让到期未成交的挂单自动撤销并退回保证金，这样钱不会卡住。

## Implementation Decisions

**模块**

- 新增 `futures-rules`：纯函数，不读时钟、不碰文件。公允价 OU、做市报价、撮合优先级、费用拆分、强平价、交割价、净额结算的算式全在这里。
- 新增 `futures` store：账本、持仓、挂单、成交、保险基金、`seq`；原子写 + 30 秒节流；坏文件按空市场运行且不写回。
- 新增 5 种报文 kind：`futures-hello`、`futures-order`、`futures-cancel`、`futures-settle`、`futures-sync`。改 `protocol.js` 需同步 `PACKET_TYPES`、`buildPacket`、`parsePacket`、`encodeXxx`、常量区，以及协议快照测试与 `docs/protocol.md`。
- service 侧接四件事：store 创建（失败降级为"期货不可用"）、报文分派（**不能落到 else**，else 是 `room.observeBeacon`）、tick 注册（每 15 秒更新公允价、每根撮合与结算）、dispose 时置 null。
- desktop 侧新增独立窗口与 IPC，照盘口窗那套（bounds 持久化、preload 白名单、`pluginWindows()` 登记）复制一份。

**合约**

- 代号 `<crop>-<YYYY>W<WW>`；周一 00:00 本地时间上市，周五 20:00 到期；作物目录驱动，只含有底价的作物。
- 1 张 = 100 个作物；24/7 交易，到期日照常交易到 20:00。
- 交割价 = 19:00–20:00 四根 15 分钟收盘价的算术平均。
- 到期：现金交割（默认），或玩家主动"转现货"（原子两步：按公允价成交现货 + 平掉等量合约）。

**价格**

- `fair = index × exp(ou)`；`ou` 的更新 `ou += -ln2/halfLife × dt × ou + σ × sqrt(dt) × normal()`。
- `normal()` 由散列派生而不是 `Math.random`，保证同一 `(种子, 时间)` 在所有机器上可复现。
- 做市：`bid = fair × 0.998`、`ask = fair × 1.002`，数量上限由风控参数决定。

**账本（`futures.json` v1）**

- 顶层：`version`、`epoch`（每次启动换新，用于结算幂等）、`host`、`accounts`（`balance` + `marginUsed`）、`contracts`、`positions`、`orders`、`trades`（硬截 500）、`insurance`、`seq`、`weekStats`。
- 不存强平价，由 `entry / leverage` 派生；读时重算，避免存档与规则漂移。

**资金与费用**

- 充值用农场的扣款 API，提现用加币 API 并按 1e6 上限分批，核对实收数量（加币超限会静默截断）。
- 开仓：保证金从 `balance` 划到 `marginUsed`；`qty = floor(名义 / (价 × 100))`，最少 1 张。
- 费用：taker 0.1% 名义、价差 0.2% 两侧、交割 0.1%；90% 销毁、10% 进 `insurance`。
- 杠杆档位 1×/3×/10×/20×。

**结算与幂等**

- 每根结束：撮合 → 强平检查 → 计算每人净额 → `seq += 1` → 广播 `futures-settle {epoch, seq, balance, marginUsed, delta}`。
- 接收端按 `(epoch, seq)` 去重，`seq` 回退直接丢弃。
- 丢包不重传：peer 每 30 秒发 `futures-sync {epoch, lastSeq}`，房主补发缺的 delta；差距过大回一份账户快照。

**权限与风控**

- 任何局域网玩家都能开户，不设批准制。补偿性约束：单账户日交易额 5,000 币、同时持仓名义 20,000 币、同源地址订单限速 20 包/10 秒。
- 房主在 `futures-hello` 时把 `deviceId` 绑到源地址，之后的订单只认该地址；价格、成交、余额全部房主算，客户端只发意图。
- 不做 hash 链审计。

**失败路径**

- 房主掉线：市场冻结；10 分钟未回按最后公允价强制平仓，托管余额退回各自农场。
- 到期时仍有挂单：全部撤销，保证金回托管账。
- 存档损坏：空市场运行、不写回、窗口提示。

## Testing Decisions

**好测试的标准**：只断言外部行为——"给了这些输入，账户余额和持仓变成什么"，不断言内部字段顺序、不 mock 私有方法。能对着 store 的公开方法测的，就不要下沉到函数级。

**唯一的测试缝**：`createFuturesStore(dir, { now, farm, log })`。

- `now` 可注入 → 不依赖真实时钟，直接构造"周一 09:00""周五 19:59""周五 20:00"三个时刻。
- `farm` 可注入 → 用内存假农场，不写用户存档。
- 这是现有代码已经在用的形状（`createMarketStore(dir, { log, now })`），**不新增缝**。

**分层测法**

- 规则层（`futures-rules`）：纯函数直接测——OU 的均值回归方向与边界、撮合的价格优先/时间优先、强平顺序、费用拆分到分、交割价取 4 根均价。
- 账本层：同一个 store 缝，跑"充值 → 开仓 → 强平 → 交割 → 提现"整条链，断言余额与 `marginUsed` 守恒。
- 协议层：`encode/parse` 往返 + 快照；跨机器语义用 `connectedPair()`（两个真 service 各绑 127.0.0.1 真 UDP，照 `trading-e2e.test.js` 的写法），覆盖丢包补洞、乱序、重放、deviceId 冒用。
- 窗口层：IPC 只做"payload 形状 + 白名单"，照 `board-window.test.js`。

**先有的类似测试**（照抄它们的骨架）：`test\market-index.test.js`（纯函数 + 指数加权）、`test\trading-rules.test.js`（规则边界）、`test\trading-e2e.test.js`（双机净额结算的最近亲）、`test\board-window.test.js`（窗口 IPC）。

**验收**：新增用例 ≥ 60；现有 1044 个用例保持全绿；`npm run check` 一次通过。

## Out of Scope

- 永续合约、资金费率、跨周持仓（合约周五到期就结束）。
- 期权、期货组合、跨品种价差合约。
- 互联网联机（只在局域网内，沿用现有 UDP 发现）。
- 真实货币、任何链上资产。
- 逐笔结算、按天结算（只做每根净额）。
- 改 `trading.js` 的盘口规则或价格公式（盘口原样保留）。
- NPC 对手盘（对手要么是做市商，要么是真人）。
- 历史 K 线的多周期切换（期货窗只给本周合约的 15 分钟图）。

## Further Notes

- **三段灰度**：影子模式（撮合与结算全跑，不碰 `farm.json`，建议跑满一周对账）→ 现金结算（单账户日额 5,000 币）→ 实物交割。回滚 = 关窗口 + 托管余额原路退回 + 存档打 `disabled` 标记（不删数据）。
- **与盘口的关系**：盘口是"街机"，期货是"市场"。盘口不改，玩家想稳赚去盘口，想对赌来期货。两者共用同一批作物与硬币，但账本完全隔离。
- **为什么不是零和**：做市商的价差和费用会把钱从系统里抽走（90% 销毁），长期看所有玩家合计是负和的——这正是它比盘口诚实的地方。
- **已知不服帖**：现有 UDP 没有时钟同步，所以结算只能以房主时钟为准；peer 的 `at` 仅用于展示，不参与任何计算。

## 实现（2026-11-17，票 92–99）

- **纯规则** `src/futures-rules.js`：合约（周一 00:00 上市 / 周五 20:00 到期）、15 秒一步的均值回归
  公允价（`OU_SIGMA = 0.004`、`OU_HALF_LIFE_MS = 30min`）、做市报价（`MM_SPREAD = 0.002`）、
  一手 `LOT_SIZE = 100`、taker / 交割费 `0.1%`（`FEE_INSURANCE_SHARE = 0.1`、其余销毁）、
  四档交割收盘（19:15/19:30/19:45/20:00 算术平均）、杠杆 1/3/10/20、灰度档位与
  `DAILY_NOTIONAL_CAP = 5000` / `POSITION_NOTIONAL_CAP = 20000` 白名单。
- **账本** `src/futures.js`：`futures.json` v1（托管账户、仓位、挂单、成交流水、保险基金与
  `shortfall`、`mode`/`dayStart`/`dayNotional`/`pending`/`disabled`、对账锚点
  `farmAnchor`/`farmIn`/`farmOut`）；每 15 秒盯市 + 每根净额结算，逐 15 秒扫描强平，
  强平/交割亏空由保险基金兜底、余额永不为负；`setMode` / `reconcile` / `rollback`。

  `futures-hello` / `futures-announce` / `futures-settle` / `futures-sync` / `futures-trade`
  五包 + 字段白名单、`(epoch, seq)` 幂等、`mode`/`pending` 白名单、4 KiB 上限。
- **宿主接线** `src/service.js`：动作分发（open/close/place/cancel/convert/deposit/withdraw/
  settle/mode/rollback/reconcile）、`/state.futures`、窗口推送、同源 20 包 / 10 秒限速、
