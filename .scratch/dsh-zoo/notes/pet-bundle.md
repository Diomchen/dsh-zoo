# 宠物串门 · 行李清单（草案）

一句话：**宠物来串门，自带长相和状态；dsh-zoo 只负责送、收、画、检查。**

这份东西不是协议定稿，只是把"哪些东西该跟宠物走、哪些该留在家里"摆到一页纸上。

## 为什么

现在 dsh-zoo 只认识 dsh-pet 的素材目录。别人换一个宠物插件，就看不懂。
如果每来一个新插件就打包一套素材，包会无限长，而且永远慢一步。

所以把"宠物内容"从 dsh-zoo 里拿出去，换成一张所有插件都能填的清单。

## 三样行李

| 行李 | 是什么 | 谁提供 | 跨端吗 |
|---|---|---|---|
| 长相 | 素材包：清单 + 动作视频（webm） | 宠物插件 | 是（给地址，或串门时带） |
| 状态 | 我现在在播哪个动作 | 宠物插件 | 是（一句话） |
| 话 | 气泡里想说什么（可选） | 宠物插件 | 是（纯文本，限长） |

## 谁干什么

**宠物插件（在对方家里）**

- 监控本机的 DSH——这是它自己的事，dsh-zoo 不碰
- 决定宠物现在干什么
- 按清单暴露素材和状态
- 不需要把自己的代码交给任何人

**dsh-zoo（串门的两端）**

- 发现、放行、串门、记录（已有）
- 收行李、存行李、在公共桌布上按状态播放
- 检查行李安不安全
- **不认识任何具体插件**

> 注意：监控代码不跨端。搬过来的只有"它现在是什么状态"这句话。

## 两张最小接口

### 1. 清单（对方机器上）

```json
{
  "id": "corgi",
  "name": "楼下的柯基",
  "size": 220,
  "actions": {
    "idle":  { "file": "idle.webm",  "loop": true },
    "sleep": { "file": "sleep.webm", "loop": true },
    "code":  { "file": "code.webm",  "loop": true }
  },
  "bundle": "https://192.168.1.8:45873/pet/bundle.zip",
  "hash": "sha256:..."
}
```

### 2. 状态（本机插件 → dsh-zoo，跨端只带小字段）

```json
{ "action": "code", "say": "在写代码", "facing": "left" }
```

视频永远不塞进心跳或串门报文，只走素材地址。

## 三级兼容

- **L0 只报动作名**（dsh-pet 现在这样）：本机有同名素材就用，没有就通用小人。
- **L1 带清单和素材地址**：完整长相，动作对得上。
- **L2 带语义标签**（working / eating / sleeping）：连素材都没有时，通用小人也能表达"在干嘛"。

## 降级表

| 对方给了什么 | 你显示什么 |
|---|---|
| 清单 + 素材 | 完整宠物 |
| 只有动作名 | 本机同名素材，没有就通用小人 |
| 什么都没有 | 通用小人（名字 + 颜色） |
| 奇怪的东西 | 拒收，不影响别人 |

## 安全底线

- 只收 webm，限大小、限时长
- 文本转义、限长
- hash 对不上不收
- 只连局域网地址
- 一个访客坏了，不能影响其他访客和串门

## 不做

- 不做通用动画格式（GIF / Spine / Live2D）
- 不做跨端监控（监控只在宠物自己家跑）
- 不做远程控制（不能指挥别人的宠物）
- 不替对方安装插件

## 要你拍板的三件事

1. **素材包**：串门时推过来，还是给地址去拉？
   我建议拉：按需、省流量、好缓存。
2. **动作 id**：自由字符串，还是固定一张语义表？
   我建议自由 id + 可选语义标签，否则每加一个动作都要改标准。
3. **气泡**：跨端默认开不开？
   我建议默认开但限长，因为"它在说什么"是串门最有意思的部分。
