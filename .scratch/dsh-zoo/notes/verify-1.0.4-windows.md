# dsh-zoo 1.0.4 · Windows 多屏“黑边”复测

验证日期：2026-11-06
验证包：`dsh-zoo-1.0.4.tgz`（324,265 B，58 files）
SHA-256：`62f9d251d2f1935e02d82136183dfbbf8211c3ec573b73996c454ccdb1a82617`
基线：1.0.3 + 未提交的「地面带 / 黑区修复」

> 这是 1.0.3 的补丁包，只改多屏地面与诊断；1.0.3 清单里的其它项目继续适用。

## 1.0.3 到底哪里漏了

1.0.3 已经按屏取地面，但松手时只把 **y** 夹回某块屏的底边，**没有夹 x**：

- 高屏在左、矮屏在右时，把宠物拖到矮屏下方的黑区（例如高屏 2560×1440、矮屏
  1920×1080，落在局部坐标 x≈2600、y≈1300）。
- “最近的那块屏”按 2D 距离算成了左边的高屏，y 夹回高屏底边（1440），x 仍停在
  2600（矮屏的 x 范围里、但 y 在矮屏下面）——于是宠物留在矮屏下方的黑区里。

1.0.4 改成**地面带**：

- `shared.walkBands()` 把底边相同且水平相邻的屏合成一条带；高度不同的屏各自一条带。
- **走路只在当前带内**：x 夹在带的左右边界、y 贴带底边。异高时走到接缝就停住，
  不会再走进矮屏下方的黑区；同高并排的屏仍是一条带，可以来回走。
- **松手**用 `shared.confineBodyToBand()`：x、y 都夹回落点所在的带。黑区里松手会
  回到脚下那块屏（先按水平范围选带，不会被旁边更近的高屏抢走）。

## 安装

和 1.0.3 一样，只把包名换成 `dsh-zoo-1.0.4.tgz`；**退出 DSH → 换包 → `pnpm install`
→ 重新打开 DSH**。速度优先时只换 helper 也能验证地面带，但 `/dsh-zoo/desktop` 新增的
`status.displays` 需要宿主也是 1.0.4。

## 重点复测（先测这一组）

用“高屏 + 矮屏”的摆法，左右各试一次：

- [ ] 把宠物拖到**矮屏下方 / 接缝旁的黑区**再松手：宠物回到矮屏内，不再消失
- [ ] 从高屏底部水平拖向矮屏，在接缝附近松手：回到矮屏（不卡在黑区）
- [ ] 快速拖进黑区再甩手（带投掷速度）：同上
- [ ] 异高时让宠物自己走到接缝：**停在屏边**（预期行为），不跨进黑区
- [ ] 同高的两块屏：仍然可以从一块走到另一块（地面带合并）
- [ ] 单屏：行为与 1.0.3 完全一致
- [ ] 拔掉任意一块屏：宠物回到剩下的屏，不留在黑区

## 如果还出现黑边

`/dsh-zoo/desktop` 现在带三组数：

- `status.displays`：每块屏的 `bounds` / `workArea` / `scaleFactor` / `primary`
- `helperStatus.bounds`：窗口实际覆盖的 DIP 矩形
- `helperStatus.floors`：随场景下发的每块屏局部矩形

把这三组 + Windows 显示设置截图（分辨率、缩放百分比、排列）发回来。判读：

- `displays` 的 `workArea` 本身有重叠/缝隙，或 `bounds` ≠ 它们的并集 → 是混合 DPI 的
  坐标问题（和地面带是两回事），需要另做坐标换算。
- 三组数都正常、`floors` 也覆盖了矮屏，但宠物仍进黑区 → 把当次松手的屏幕坐标
  （或录屏）带上，按地面带再查。

## 预期变化

- 异高屏之间**不能再走路跨屏**（走到接缝停住）；跨屏请用拖拽。这是为了不进入黑区。
- 同高相邻屏不受影响。
- 混合缩放比下非主屏一侧仍可能略糊（Chromium 一扇窗只有一个 device scale factor）。
