# 38: 扫描入口的三个漏洞（Windows 现场发现两个，一个没撞上）

**What to build:** 「扫描外观」判重对着磁盘上的 `skin.json`，坏文件永远报 409，
干净机器上第一次扫描不会把自动源（鱼）顶掉。

**Blocked by:** 37

**Status:** done

来由：2026-11-05 的 0.5.6 Windows 验收（[回执](../notes/verify-0.5.6-windows-result.md)）。
对方修了两条并附了补丁，第三条是我在写复现测试时发现的——他们那台机器上 `skin.json`
已经存在，所以撞不到。

### 现场发现的两条

1. **没有新素材时，坏 `skin.json` 被当成成功。** 旧代码先算 `fresh`，空了就直接返回
   200「没有发现新的素材包」，根本没解析文件。用户手改坏文件、还没重载时，缓存里那只猫
   还是"已知"，于是扫描报成功——而文件已经读不出来。
2. **判重用进程缓存。** `knownIds` 来自启动时的 `skinSources`。手动删掉一条、不按
   「重载配置」，扫描仍认为它在，永远补不回来。

### 第三条（空白机器才会撞）

`skin.json` 不存在时，注册表就是自动源（dsh-pet 的鱼）。扫描若只写扫到的猫，
新文件一落地就把自动源顶掉了——**鱼消失，当前皮还会变成猫**。现场没撞上是因为他们的
`skin.json` 早就存在。

- [x] `readSkinEntries(dir)`：坏文件抛，`{exists, entries}`；与 `loadSkinSources` 的
      「坏文件回落自动源」分工明确
- [x] 判重改成对着文件（而不是进程缓存）；文件不存在时用当前的自动源
- [x] 文件不存在 → 把自动源一起写进新文件；已存在 → 只追加新的
- [x] 校验放在 `loadSkin()` 之前：坏文件不该先把当前皮悄悄换掉再失败
- [x] `skin.json` 空数组 = 只校验不落盘（`appendSkinSources` 本来如此）
- [x] 单测 3 条：手改未重载仍能补回、改坏后报 409 且不覆盖、空白机器保住自动源
- [x] 负向验证：把「空白机器」那条的种子逻辑去掉，测试立刻变红
- [x] 全量 524 项全绿

> 不做：给扫描加「移除」（减法仍是删一行）；把 `loadSkin()` 提到校验前（会带来"失败但
> 先改了状态"的副作用）。

> 验收：干净机器（无 `skin.json`、装了素材包）→ 点扫描 → 文件里是 `dsh-pet` + `maodie`，
> 当前皮仍是鱼；把文件写坏再点 → 409，文件原样。
