# 35: 皮自带尺寸

**What to build:** 每张皮可以带自己的显示尺寸；换皮之后本机宠物的大小跟着变，访客仍用默认尺寸。

**Blocked by:** 32（换皮）、33（素材根目录随皮走）

**Status:** open

来由：`skin.json` 的 `size`（缺省 `DEFAULT_SIZE = 462`）今天只是一个数字——`shared.petScene`
给**所有**宠物算同一个 size（工作区的 12%，夹在 16–176），`size` 只随 manifest 出去，没人读它。
所以 `dsh-pet` 和 `maodie-pet` 的 462 长得一样大，而两套素材的构图未必是同一个比例。

票 32 的 ADR-0013 §决定 7 把「尺寸跟皮走」记成了"另开票"，这一票就是那张票。

## 先定一件事：`size` 是什么单位

这是整张票唯一真正的设计问题，其余都是布局工作。三个选项：

- **A. 相对比例**：以 462 为 1.0，`factor = size / 462`，乘在现在的基准尺寸上。
  好处是现有两份素材都不用改；坏处是 462 这个魔数等于进了协议。
- **B. 绝对像素**：`size` 直接是包围盒边长，上限抬到比如 512。
  直观，但在 1440 高的屏上 462 太大，而且和「工作区 12%」的现有基准打架。
- **C. 显式 `scale`**：`size` 继续只做 manifest 元数据，另加 `scale: 1.0`（0.5–2）。
  最干净，但要给 `skin.json` 加字段、给老配置留缺省。

建议 A：不用迁移，且 462 今天就是缺省值。选完写进 ADR，并把 ADR-0013 §决定 7 改掉。

## 必须一起想清楚的

- **布局**：现在 N 只宠物按**同一个** `width` 均分（`span` / `x` 都用它）。不同宽度要改成
  按累加宽度定位，否则大皮会压到小宠物身上。
- **地面与标签**：`height = size + labelHeight` 每只各算各的，但 `groundY` 必须是同一条
  地平线——不能各降各的，否则一排宠物高低错落像摔倒了。
- **换皮瞬间**：只换包围盒，保留现场位置（`reset:false`），不能把宠物丢回出生点。
- **访客**：访客没有本机皮（`skinId` 是对方的），这一票里一律用默认尺寸。
- **手动缩放**：现在没有这个 UI（`updateBody({size})` 只有窗口 resize 会走），所以不存在
  "用户调过又被皮覆盖"的冲突；将来加的话优先级是 用户 > 皮 > 默认。

- [ ] 定 `size` 语义并写进 ADR（含夹取范围：沿用 16–176，还是按新语义重定）
- [ ] `petScene` 支持逐只 `size`：每只自己的 `width` / `height`，横向按累加宽度排，
      共用一条地平线
- [ ] 服务端只给 `self` 带当前皮的尺寸，访客不带
- [ ] 换皮后场景签名变化触发重发；渲染端按新包围盒重建 body，位置保留
- [ ] 超大/超小的皮不能把宠物挤出工作区，也不能把名字标签压没
- [ ] 单测：两种尺寸同屏时的 x 间距与地面线、逐只 `width`/`height`、换皮后尺寸跟着变
- [ ] 全量测试全绿

> 不做：访客自带尺寸（要改清单字段，另开票）；用户手动缩放 UI；按素材真实宽高比自适应
  （alpha 边界不在 manifest 里，得先有办法量出来）。

> 验收：给 `maodie-pet` 配一个与 `dsh-pet` 不同的 size，切过去时宠物大小立刻跟着变，
> 位置不跳，标签不被裁；两只宠物同屏时按各自宽度排开，不叠在一起。
